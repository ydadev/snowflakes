# Участие в разработке

Проект ведётся по [ROADMAP](docs/ROADMAP.md). Текущая работа указана в [DEVELOPMENT_STATUS](docs/DEVELOPMENT_STATUS.md), правила репозитория — в [AGENTS.md](AGENTS.md).

## Порядок изменения

1. Выбрать задачу текущего этапа и прочитать её требования.
2. Реализовать минимальный законченный результат с проверкой поведения.
3. Запустить относящиеся к изменению проверки и записать фактический результат.
4. Обновить статус, а при необходимости ТЗ, архитектуру и ADR.
5. Проверить diff, состав файлов и метаданные на приватную информацию.
6. Создать коммит с кратким описанием проблемы и результата.

В PR указывать задачу этапа, поведение после изменения, способ проверки и оставшиеся ограничения. Результаты ручных проверок отделять от автоматических.

## Проверки

Rust: форматирование, clippy, тесты и сборка Windows-клиента. PHP: проверка синтаксиса, тесты API/SQLite и установка готового пакета. Протокол проверяется общими примерами на обеих реализациях.

Команды, версии и запуск прототипов описаны в [DEVELOPMENT](docs/DEVELOPMENT.md). На Windows полный набор запускается tools/check.ps1 после npm ci. Интерактивные проверки фиксировать отдельно по [TEST_RESULTS_P1](docs/TEST_RESULTS_P1.md).

## Данные и окружение

Использовать синтетические данные и loopback в примерах. Реальные параметры размещения и реквизиты не включать ни в изменения, ни в сообщения/изображения PR. Частные файлы окружения игнорируются Git.
