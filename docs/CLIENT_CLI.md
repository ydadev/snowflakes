# Windows-клиент: запуск и команды

Клиент находится на этапах P2/P3/P4. Работают процесс, трей, панель, местное хранение, IPC, первый физический снег с накоплением и капли/брызги дождя. Во время рисования status сообщает renderer=d3d11_direct2d, rendering=true, число частиц активного режима и видимых слоёв мониторов. Лужи и HTTP ещё не подключены. Размер луж пока сохраняет предпочтение, но не создаёт воду.

## Запуск

Из корня собранного проекта в Windows PowerShell:

~~~powershell
Start-Process -FilePath .\target\release\snowflakes.exe -ArgumentList '--ensure-running' -WindowStyle Hidden
.\target\release\snowflakes.exe --status --json | ConvertFrom-Json
~~~

Без аргументов EXE запускает приложение и открывает настройки; повторный такой запуск открывает панель существующего экземпляра. Новый экземпляр остаётся работающим до выхода. Start-Process позволяет не ждать его завершения. Повторный --ensure-running возвращает статус существующего процесса и не снимает ручную паузу.

Настройки читаются из %LOCALAPPDATA%/Snowflakes. Для отдельного стенда при запуске можно передать --data-dir с абсолютным путём; имя IPC всё равно определяется пользователем и сеансом, поэтому отдельный каталог не создаёт второй обычный экземпляр в том же сеансе.

## Обнаружение мониторов

~~~text
snowflakes.exe --list-monitors --json
~~~

Команда возвращает code, message и массив monitors с полями id, persistent, primary, left, top, width, height. Координаты и размеры — физические пиксели виртуального рабочего стола; координаты могут быть отрицательными. Код успеха — 0. Команда работает без запущенного клиента, не включает эффект, не открывает настройки и не снимает ручную паузу.

ID вычисляется из интерфейса устройства Windows, а не временного HMONITOR. persistent=true означает наличие такого интерфейса; это не гарантия неизменности при смене порта, док-станции или драйвера. При fallback по имени GDI возвращается persistent=false. Исходные пути устройств и их имена не выводятся.

Для selection=selected используются эти ID в monitor_ids. Прежние ID раннего прототипа, основанные на HMONITOR, требуется заменить после нового перечисления. Автоматическое сопоставление таких ID не выполняется. Режимы all и primary не требуют изменений. Решение: [ADR 0014](adr/0014-display-identities-and-accumulation-masks.md).

## Выбор мониторов

~~~text
snowflakes.exe --monitors all
snowflakes.exe --monitors primary
snowflakes.exe --monitors selected display-a display-b
~~~

Последняя строка содержит синтетические ID; подставьте точные ID из --list-monitors --json. Режим и список применяются вместе к местному профилю. selected принимает от 1 до 16 разных ID; all/primary очищают список. Команда не запускает приложение и не снимает паузу. При включённой галочке «Слушать сервер» изменение отклоняется.

В панели выберите «Все экраны», «Основной экран» или «Выбранные». В последнем случае выделите нужные строки щелчком или Пробелом, затем нажмите «Применить экраны». Остальные погодные поля по-прежнему применяются сразу. Номера строк упорядочены по расположению экранов и не совпадают обязательно с номерами Windows.

Список обновляется раз в две секунды. Отключённый сохранённый экран остаётся в списке; отсутствие всех выбранных экранов не включает эффект на остальных. Закрытие панели отбрасывает неприменённый выбор. Уже отправленная команда выполняется независимо от закрытия панели. Решение и границы: [ADR 0015](adr/0015-monitor-selection-controls.md).

## Управление существующим процессом

~~~text
snowflakes.exe --status --json
snowflakes.exe --settings
snowflakes.exe --server-url http://127.0.0.1:805/
snowflakes.exe --pause
snowflakes.exe --resume
snowflakes.exe --clear
snowflakes.exe --follow-server off
snowflakes.exe --set mode=snow
snowflakes.exe --set flake_size=150
snowflakes.exe --set flake_visibility=125
snowflakes.exe --set rain_intensity=70
snowflakes.exe --set puddle_size=35
snowflakes.exe --set target_fps=30
snowflakes.exe --set battery_saver=true
snowflakes.exe --quit
~~~

Команды управления не запускают приложение, если его нет. Погодные изменения в серверном режиме отклоняются. Снятие галочки и погодные значения сохраняются в TOML до применения; ошибка записи оставляет прежние значения.

| Ключ --set | Значение |
| --- | --- |
| mode | snow или rain |
| snow_intensity, rain_intensity | Целое 0–100 |
| drift_size, puddle_size | Целое 0–100 |
| flake_size | Целое 25–200; 100 — базовый разброс размеров |
| flake_visibility | Целое 0–200; 100 — базовый вид |
| opacity | Целое 10–100 |
| snow_wind, rain_wind | Целое от -100 до 100 |
| effects_enabled | true или false |
| target_fps | 30 или 60 |
| battery_saver | true или false |
| snow_on_windows, snow_on_ground | true или false; независимые опоры накопления |
| snow_melting | true или false; обычное таяние |
| cursor_enabled | true или false; взаимодействие с курсором |

--settings запрашивает открытие панели существующего процесса; успешный ответ settings_requested подтверждает постановку запроса. --server-url сохраняет нормализованный адрес без реквизитов и параметров запроса; пустая строка удаляет его. Адрес в JSON-ответ не включается. Изменение адреса сбрасывает серверный профиль в памяти и отменяет прежний запрос, сохраняя местные значения.

--sync-now пока возвращает network_not_connected. Этот результат не считается успешным опросом сервера.

## Панель настроек

Левое действие значка трея и пункт «Настройки» открывают немодальную панель. По умолчанию включена галочка «Слушать сервер». Для местной регулировки её нужно снять; интенсивность снега/дождя и размер сугробов/луж сохраняются независимо. Добавлены независимые размер и заметность снежинок в процентах. 100% соответствует базовому виду, разные радиусы не становятся одинаковыми. Изменения применяются сразу, кнопка «Сохранить» относится к адресу.

При включённой галочке погодные поля доступны только для чтения. Без серверного профиля показаны ожидание и прочерки. Панель показывает состояние связи; до подключения транспорта кнопка «Проверить сейчас» выключена. Поля отражают эффективные ограничения GPO.

Галочки «Снег на окнах», «Снег внизу экрана», «Таяние снега» и «Смахивание курсором» сохраняются независимо. Выключение накопления на выбранной опоре или размер сугробов 0 плавно удаляют её снег примерно за две секунды активного времени. Снегопад продолжается; пауза монитора приостанавливает удаление. Повторное включение сохраняет оставшийся материал. Отключение обычного таяния не мешает явному выключению накопления.

Закрытие панели оставляет процесс в трее. Пауза, очистка и выход сохраняют отдельное значение. Раскладка учитывает DPI и предусматривает вертикальную прокрутку; интерактивная матрица масштабов ещё не подтверждена.

В панели доступны выбор 30/60 FPS и галочка «Экономить заряд батареи». При включённой экономии питание от батареи/ИБП либо системный Battery Saver ограничивают цель 30 FPS и отключают дополнительные тени/свечение. Интенсивность, скорость движения и пределы накопления сохраняются. Возврат к сети восстанавливает выбранное качество, если системная экономия выключена. Профиль сервера и ограничения Windows имеют прежний приоритет.

В status поля effective_target_fps и reduced_detail показывают выбранную цель и сокращение графических деталей. Это не замер частоты кадров: при паузе цель сохраняется, но rendering=false; до отчёта графического worker цель равна 0.

## Автоматический вход и выход

--ensure-running --from-logon проверяет StartAtLogon и сохранённую настройку startup.enabled. По умолчанию личный автозапуск выключен. Команда не создаёт задания или GPO.

После явного выхода marker текущего сеанса блокирует повторный автоматический запуск с --from-logon. Он возвращает код 0 и сообщение start_suppressed, не создавая процесс. Явный Start без --from-logon снимает это подавление. Автоматические задания и проверки работоспособности должны использовать --from-logon; обычный --ensure-running считается явным Start.

Marker связан с Session ID и AuthenticationId входа, хранится рядом с конфигурацией и не публикуется. Проверки нового входа, перезагрузки и очистки старых marker остаются в матрице P6/P7.

## Коды завершения CLI

| Код | Значение |
| --- | --- |
| 0 | Успех; start_suppressed явно отмечает подавленный автозапуск |
| 1 | Внутренняя ошибка или неподключённая подсистема |
| 2 | Неверная команда, параметр или редактирование профиля только для чтения |
| 3 | Экземпляра нет или он закрывается |
| 4 | Запрет политики или автозапуска |
| 5 | Нет интерактивного сеанса для GUI |
| 6 | Тайм-аут |

Ответы команд управления имеют JSON-поля code, message и status; команда обнаружения вместо status возвращает monitors. Сообщения машинные и не зависят от языка интерфейса. status содержит версию, PID, сеанс, источник, причины паузы, effective settings, признак ограничений, particle_count и monitor_count. Последнее поле показывает число слоёв, помеченных видимыми. Адрес, SID, hostname и токен не выводятся.

Сейчас адресуется текущий пользователь и сеанс. Административное обращение к другому сеансу ещё не реализовано.

Debug-сборка имеет --test-headless и --test-namespace для изолированных автоматических тестов процесса. Они недоступны в release и не подменяют проверку GUI. В тестах используются временные каталоги, а не рабочая конфигурация.
