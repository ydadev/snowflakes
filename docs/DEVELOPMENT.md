# Локальная разработка

Исходники пока являются техническими прототипами P1. Снег, дождь, трей, синхронизация и установщик ещё не готовы.

## Проверенные инструменты

| Инструмент | Проверенная версия |
| --- | --- |
| Rust / Cargo | 1.99.1, x86_64-pc-windows-msvc |
| MSVC | 19.44.35228 |
| Windows SDK | 10.0.26100.0 |
| windows-rs | 0.62.2 |
| PHP | 8.3.36 NTS x64 |
| SQLite в PHP | 3.53.4 |
| Node.js / npm | 24.18.0 / 11.16.0 |
| Ajv | 8.20.0 |

Rust фиксируется в rust-toolchain.toml, зависимости — в Cargo.lock и package-lock.json. Нужны C++ Build Tools и Windows SDK. Для PHP включить PDO_SQLITE и SQLite3; JSON и sessions поставляются с PHP. Node.js используется только для проверки JSON Schema.

Установка инструментов не должна менять глобальные настройки Git. Допускаются переносимые инструменты в игнорируемом .local/tools. PowerShell-проверка распознаёт локальные Rust/PHP, если они там установлены.

## Автоматические проверки

На Windows после установки зависимостей:

~~~powershell
npm ci --ignore-scripts --no-audit --no-fund
./tools/check.ps1
~~~

Скрипт проверяет форматирование, clippy с отказом при предупреждениях, тесты, release-сборку Rust, JSON Schema, синтаксис PHP, SQLite и HTTP API. Для нестандартного PHP передать -Php с путём к php.exe.

HTTP-тест запускает дочерний PHP только на loopback и свободном временном порту, создаёт синтетическую БД и затем удаляет собственные временные файлы. Параметр -SkipHttp оставляет явный результат Not run и не заменяет полный прогон.

Отдельные команды:

~~~text
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --workspace --release --locked
npm run test:schema
php server/tests/run.php
php server/tests/http.php
~~~

Тесты контракта используют [общие случаи](../protocol/fixtures/configuration-cases.json). Описание полей и лексических правил — в [protocol/README.md](../protocol/README.md).

## GPU-прототип Windows

~~~text
cargo build -p snowflakes-client --locked
target/debug/snowflakes.exe --input-probe
target/debug/snowflakes.exe --overlay-prototype 30 --exercise-recovery
~~~

Окно input-probe запускать отдельным процессом. Оно содержит только синтетические данные и счётчики щелчков, клавиш и прокрутки. GPU-прототип создаёт по одному слою на монитор, рисует тестовые прямоугольники и сам завершается через заданное число секунд, от 1 до 600.

С опцией exercise-recovery на 3–5-й секунде нет кадров; примерно на 8-й секунде пересоздаются окна и графические ресурсы. Это проверка управляемого пересоздания, не настоящий сброс драйвера. Счётчик кадров служит диагностикой, а не результатом приёмки производительности.

Проверить видимость полупрозрачного маркера, мышь через него, клавиатуру, прокрутку, перенос окна и сохранение фокуса. Повторить на Windows 10/11, нескольких DPI и мониторах. Успех COM-вызовов не подтверждает визуальный результат и ввод.

## PHP-прототип

~~~text
php -S 127.0.0.1:805 -t server/public
~~~

Публичные маршруты:

| Запрос | Ответ |
| --- | --- |
| GET api.php?action=health | 200, приложение доступно |
| GET api.php?action=ready | 200 с установленной тестовой БД или 503 без неё |

Проверка ready не создаёт БД и не выполняет миграции. Тесты создают и проверяют её через внутренние классы приложения. Браузерный установщик, административный вход и клиентские маршруты появятся в P5. Корень HTTP — только server/public; сервер разработки не предназначен для рабочего размещения.
