# Локальный сбор ресурсов Windows-клиента

Сборщик — отдельный инструмент разработки. Он читает уже работающий клиент и не запускает эффект. Нужны Windows x64 и PowerShell 5.1+, доступ к процессу текущего пользователя и локальным performance counters. Недоступные показатели не препятствуют сбору остальных, но не считаются нулевыми.

Из корня проекта, при существующем каталоге .local:

~~~powershell
$clientExe = (Resolve-Path .\target\release\snowflakes.exe).Path
$outputPath = Join-Path $PWD '.local/resources.ndjson'
.\tools\measure-resources.ps1 -ClientExe $clientExe -OutputPath $outputPath -Scenario paused -Seconds 60
~~~

Сценарий paused требует rendering=false. Для уже включённого на отдельном тестовом рабочем столе снега можно выбрать snow-baseline или snow-stress; они требуют активного режима snow, но не меняют профиль или нагрузку. Название сценария само по себе не доказывает совпадение с базовым стендом ТЗ. Отсутствие клиента или несовпадение сценария завершают запрос, не запуская приложение.

ClientExe и OutputPath должны быть абсолютными. Файл создаётся через CreateNew, повторное использование запрещено. Seconds: 1–28800, IntervalSeconds: 1–10, WarmupSeconds: 0–60; значения по умолчанию — 60, 1 и 5 соответственно. Восьмичасовой сбор подготавливается параметром Seconds=28800, но сам этот параметр не означает проведённую проверку устойчивости.

Вызовы CLI ограничены --status --json и --list-monitors --json. После проверки PID/сеанса собираются CPU, private bytes/working set, самый занятый 3D engine процесса, сумма committed GPU memory по адаптерам и отдельный самый занятый 3D engine DWM этого сеанса. CPU нормирован по всем активным логическим процессорам. Сбор не меняет следование серверу, ручную паузу или настройки.

Формат NDJSON ограничен 64 MiB:

| Запись | Содержание |
| --- | --- |
| header | Версия и SHA256 EXE без путей, параметры сбора, ОС, CPU/RAM, GPU/драйверы, геометрия дисплеев и снимок погодного профиля |
| sample | Фактическая длительность интервала, CPU в процентах, память в байтах, состояние/значение каждого GPU-счётчика |
| state | Обнаруженное при очередном чтении изменение снимка настроек/паузы; опрос примерно раз в пять секунд |
| summary | Причина завершения, покрытие интервалов, взвешенные средние, максимумы, изменение private bytes и число обнаруженных изменений |

Для каждого GPU-показателя state=available позволяет использовать value, включая настоящий 0. unavailable оставляет value=null и диагностический code. В итогах mean_when_available учитывает только covered_seconds; неполное покрытие нельзя выдавать за среднее всего прогона. Проценты разных engines не суммируются. DWM включает нагрузку других окон и требует отдельного фонового замера для сравнения. Значения GPU memory провайдера требуют независимой сверки перед выводом об утечке или выполнении лимита.

reason=completed означает окончание сбора, acceptance=not_evaluated сохраняется всегда. Завершение процесса, смена цели, ошибка опроса или предел файла дают частичный отчёт и ненулевой код. Отсутствие summary, обрыв строки и ошибка записи делают файл неполным. FPS и frame_interval_p95_ms пока null: целевой FPS профиля не подменяет измерение.

Сборщик не записывает адрес сервера, hostname, SID, пути профилей, содержимое или названия окон. Аппаратная конфигурация и параметры стенда предназначены для локального анализа; полные файлы хранить в .local или другом месте вне Git. На публикацию выносятся только подготовленные нейтральные результаты. Ограничения источников и реализация описаны в [ADR 0028](adr/0028-resource-collection.md), проверки — в [TEST_RESULTS_RESOURCE_COLLECTION](TEST_RESULTS_RESOURCE_COLLECTION.md).
