# Проверки кандидатов контакта

Дата: 14 ноября 2026 года. Windows 11 x64, Rust 1.99.1/MSVC, release, 28 доступных логических процессоров. P3-04. [ADR 0041](adr/0041-contact-candidates-per-body.md), [методика](MODEL_BENCHMARK.md).

Проверен поиск опор с локальным списком кандидатов на одно тело и заимствованным вектором для одной строки. Точечная геометрия, высота, маски и время удара вычисляются прежним способом.

## Сценарии корректности

| Проверка | Подтверждение |
| --- | --- |
| contact_candidates_follow_columns_and_both_swept_rows | Один список проходит между разными столбцами; изменение только начальной либо конечной строки возвращает нужную опору и ближайший удар |
| contact_candidates_keep_equal_time_order_and_recheck_filters | Окно и нижняя опора имеют одинаковую высоту; сохраняются порядок ключей, исключение источника/переднего слоя и актуальные переключатели |
| contact_candidates_recheck_height_inside_one_cell | Соседние точки в одной области индекса имеют разную высоту снега; контакт не переносится с первой точки на вторую |
| contact_candidates_support_negative_rows_and_coordinates | Отрицательные строки/координаты, движение вверх и длинная траектория к нескольким опорам |

Все четыре Passed. До общего прогона также Passed пять falling_masks и a_rising_mound_captures_overlapping_slabs_without_capturing_snow_below_a_roof. Новые тесты проверяют оптимизацию, воспроизведение прежнего дефекта Failed → Passed не заявляется.

## Контролируемый замер

A — опубликованная модель 97fe203 с повторным использованием преобразований. B — новая обработка кандидатов. В обоих один наблюдатель версии 1, seed 24301, 120 шагов прогрева, 3600 измеряемых шагов. Отдельные процессы запущены последовательно A/B/B/A для каждого сценария, без параллельной компиляции. Рабочий клиент не участвовал.

Равные по длине пары дают среднее baseline 87,839 → 52,374 мкс, снижение 40,38%; material 7,430 → 5,132 мс, снижение 30,94%. В material число шагов дольше DT: 33/7200 → 4/7200. p95 приведён для отдельных запусков; объединённый p95 не вычислялся. Это результаты одного стенда и порядка запусков.

В каждой группе совпали sampled_active_and_drift_hash версии 1, активные счётчики и массы: baseline наблюдал 309–383 тела, material — 4800 активных и 812 ожидающих частей в 128 пакетах. Наблюдатель охватывает выбранные активные состояния/преобразованные контуры и mass/pending опор; полного снимка всех внутренних полей нет.

Максимальный пик private bytes за жизнь процессов: baseline A 1,254 МиБ/B 1,289 МиБ, material A 4,762 МиБ/B 4,754 МиБ. Эти короткие замеры модели не подтверждают потребление памяти клиента или длительную устойчивость. Подготовка нагрузочной сцены измеряется отдельно, около 48–51 мс.
