# Восстановление desktop в нативных тестах

Дата: 15 ноября 2026 года. Область: необходимая основа P1/P2 для снега, только cfg(test). [ADR 0089](adr/0089-private-desktop-cleanup-diagnostics.md).

## Результат исследования

В [предыдущем Native-тесте](TEST_RESULTS_MONITOR_TRANSFER_PREPARATION.md) остаётся однократный необъяснённый ERROR_BUSY. Ограниченный повтор не воспроизвёл этот отказ. Добавлен отчёт, который при следующей ошибке сохранит исходный HRESULT восстановления/закрытия, счётчики hooks и снимок принадлежащих потоку окон. Строгость очистки не ослаблена.

| Проверка | Результат |
| --- | --- |
| 16 выполнений прежнего Native-теста без перечисления окон | Passed в debug |
| 16 выполнений с подробными фазами | Passed в debug |
| Те же два режима в release | Passed: 16 + 16 случаев |
| Контролируемый ERROR_BUSY при собственном живом окне | Passed в отдельном UI-потоке в debug/release |
| Строгий возврат/закрытие родителя после join | Passed в debug/release и общем наборе |
| Окончательный общий набор | Passed: 530 + 3 + 8 выполнений Rust, восемь smoke |
| CI окончательных исходников | Passed: [90509be](https://github.com/ydadev/snowflakes/actions/runs/43747093646) |

Каждый режим использует четыре конкурентных потока по четыре случая. В каждой из debug/release оба режима установили и сняли по 64 настоящих WinEvent-hook: всего 256 за 64 выполнения, отказов/неверных владельцев/оставшихся отслеживаемых hooks нет. Без подробного наблюдения массивы снимков пусты. Подробный режим видит 4–5 окон при живом собственном STATIC, после его удаления и перед восстановлением — ноль. Ошибок/усечений перечисления в этих снимках нет. Присутствовавшие категории IME/текстовых служб/OLE в успешных случаях не являются доказательством утечки или причины старого сбоя. Время режимов не используется как статистическое доказательство отсутствия влияния наблюдателя.

До сопоставленных режимов отдельный пилот из 16 подробных случаев также Passed. Это повторные выполнения существующего теста, не новые уникальные проверки. Итоговые 32 debug-случая и отдельная контрольная проверка считаются раздельно.

Окончательный tools/check.ps1 Passed: fmt/clippy, 530 клиентских тестов + 3 протокола + 8 release-повторов, всего 541 выполнение и 533 уникальные проверки Rust; 47 ignored. Библиотечный набор — 219 Passed. Новый контроль и прежний Native-тест прошли в одном параллельном наборе. Сохранены восемь прежних smoke-отпечатков и границы массы/пулов. Сборщики 35/31 assertions Passed в одной локальной редакции PowerShell; существующие schema 60, PHP 60+5, SQLite/HTTP Passed как регрессии компонентов. Работа над водой или сайтом не возобновлялась.

CI исходников [90509be](https://github.com/ydadev/snowflakes/actions/runs/43747093646) Passed: Windows и contract-and-php завершились success. Декодированный Windows-журнал подтвердил новый контроль, прежний Native-тест, 530+3+8 выполнений, 47 ignored и восемь прежних отпечатков. Сборщики 35/31 прошли в обеих редакциях PowerShell. Отдельный журнал контрактной задачи подтвердил schema 60, PHP 60+5, SQLite/HTTP. Диагностическая серия действительно ignored; её локальные 64 выполнения не приписываются CI. Успех CI не устанавливает причину исходного редкого отказа.

## Контроль самого отчёта

Первоначальная контрольная проверка на родительском тестовом потоке прошла отдельно, но в общем параллельном прогоне получила новый настоящий отказ при окончательном возврате: ERROR_BUSY у SetThreadDesktop и CloseDesktop. Снимок после удаления своего окна показал два невидимых окна: STATIC=0, IME=0, текстовые службы=0, OLE=1, прочие=1; отслеживаемых hooks=0. Этот Failed сохранён как наблюдение, а не заменён зелёным повтором.

Окончательный контроль создаёт своё окно на отдельном scoped UI-потоке того же процесса и невходного desktop. Он намеренно вызывает отказ, сохраняет оригинальный HRESULT, проверяет собственный STATIC в снимке и отсутствие обычной подробной фазы при выключенной диагностике. Своё окно явно уничтожается на владельце; нормальный выход потока и обязательный join предшествуют строгому восстановлению/закрытию родителя. Неизвестные окна не уничтожаются, поток не завершается принудительно. Успех этого контроля не объясняет источник двух служебных окон и не исправляет исходный Native-тест.

## Ограничения

Учёт hooks относится только к Tracker. Перечисление ограничено, снимок отражает конкретный момент, отсутствие найденных объектов не гарантирует отсутствия всех возможных ресурсов Windows. Подробное наблюдение может менять тайминг, поэтому обычный успешный путь окна не перечисляет. В CI диагностическая серия ignored; обычный контроль отчёта выполняется.

Никакая приёмка видимого снега, ресурсов полного клиента, двух мониторов/mixed DPI, Windows 10/11 целиком, реального ввода, hotplug/device loss или длительного прогона этим не закрыта. Рабочий клиент не заменялся и не получал Resume/Clear; read-only статус подтвердил manual/rendering=false. Дождь, лужи, сайт и поставка отложены.

## Повторение

~~~text
cargo test -p snowflakes-client --lib --locked platform::scene::tests::events::native_source::cleanup_probe::native_cleanup_observes_controlled_owned_window_denial_and_then_restores_strictly -- --exact --nocapture
cargo test -p snowflakes-client --release --lib --locked platform::scene::tests::events::native_source::cleanup_probe -- --include-ignored --nocapture
~~~

Обе точки сами создают/проверяют собственные невходные desktop. Ошибка восстановления остаётся ошибкой теста; не повторять серию до зелёного результата и не применять приёмы очистки к живым пользовательским окнам.
