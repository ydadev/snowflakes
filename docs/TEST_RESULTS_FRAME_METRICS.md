# Проверки счётчиков кадров по дисплеям

Дата: 13 ноября 2026 года. Среда: Windows 11, Rust 1.99.1/MSVC x64, PowerShell 7.6.9 и 5.1. Область: диагностика P2/P3; дождь/лужи Deferred.

Клиент: 211 прошедших тестов и один аппаратный тест, исключённый из обычного прогона; протокол — 3 теста. Добавлены восемь автоматических сценариев: пять модели счётчиков, HRESULT, возраст status и headless-запуск с флагом. Усилены отказы CLI. Сбор ресурсов имеет 33 проверки, обработка кадров — 23; оба набора проходят в PowerShell 7 и 5.1.

| Сценарий | Результат |
| --- | --- |
| 30/60 Present в секунду | Passed на синтетическом времени: разные распределения, число интервалов и сумма длительности |
| Пауза и повторная пауза | Passed: статистика сохранена, пауза не добавляет интервал, разрыв учитывается один раз |
| Порог 25 мс | Passed: ровно 25 мс попадает в нужную корзину, +1 нс — в следующую |
| Задержка и порядок времени | Passed: переполнение сохраняется, повторный timestamp отмечает разрыв |
| Предел ответа | Passed: 65 слоёв дают 32 записи и omitted_displays=33; даже с предельными u64 снимок короче 40 КБ |
| S_OK / S_FALSE / OCCLUDED / device removed | Passed: только S_OK считается принятым кадром, ошибка остаётся ошибкой |
| Возраст status | Passed: трёхсекундный снимок не получает фиктивный нулевой возраст |
| CLI/headless | Passed: флаг разрешён новому изолированному экземпляру, без рендерера данные не появляются; повторение, команды и работающий экземпляр отклонены |
| PowerShell | Passed: разные дисплеи и эпохи, отсутствие/null/плохие счётчики, устаревание, пропуски, разные границы, взвешенная частота, общий p95, переполнение и предел исторических ID |

Отдельная регрессия подтверждает восстановление 30-секундного стопа после устаревания снимков: свежий накопительный снимок сохраняет интервал в корзине переполнения. Возраст старой исторической базы не делает её счётчики неверными. Устаревшая база при самом начале сбора не используется, чтобы не захватить время до измерения.

## Скрытый GPU-путь

Аппаратный тест запускается отдельно с --ignored. Он создаёт слой 64×64 за пределами экрана, не показывает его и проверяет IsWindowVisible=false. Обычный Direct2D/D3D11/DirectComposition-путь выполнил четыре Present. Первый вариант ожидал S_OK и Failed: все результаты оказались DXGI_STATUS_OCCLUDED (087a0001). Теперь проверяется фактическое число S_OK, без предположения о видимости.

Повторный прогон Passed: ноль принятых кадров и интервалов. Два настоящих сериализованных снимка разобраны PowerShell: окно доступно, present_fps=0, p95=null. Подтверждены формат и отсутствие ложных кадров. Положительный нативный путь S_OK на видимом слое здесь не проверялся.

~~~text
cargo test -p snowflakes-client --lib hidden_gpu_present_results_never_invent_frame_metrics --locked -- --ignored --nocapture
~~~

Аппаратный тест исключён из CI по умолчанию из-за зависимости от D3D11-адаптера и графического сеанса. Его локальный успех не означает видимую приёмку.

## Совместимость

Новая release CLI прочитала прежний приостановленный экземпляр. Короткий сбор NDJSON v2 завершился с reason=completed, frames.supported=false и отсутствующим FPS: прежний клиент не притворяется измеренным. Ручная пауза и rendering=false подтверждены. Новая сборка подготовлена отдельно и не запускалась как рабочий эффект. Настройки, аппаратные сведения, журналы и изображения не опубликованы.

~~~powershell
.\tools\test-frames.ps1
.\tools\test-resources.ps1
~~~

## Открытая приёмка

Not run: успешные S_OK в активном видимом снегу, 10 минут на базовом стенде, многомониторная нагрузка/пласты, реальный FPS DWM и p95 показанных кадров, Windows 10, hotplug/device lost, затраты диагностики, восемь часов и полный ввод → видимый кадр CT-10. Пределы производительности не засчитаны. Интерактивная работа и рабочий эффект не возобновлялись.
