# Проверка классификации полноэкранных окон

Дата: 15 ноября 2026 года. Клиент 0.1.0, Rust 1.99.1/MSVC, Windows x64. Область: P2-02/04, OS-06. [Решение](adr/0077-fullscreen-without-collection-heuristic.md).

## Воспроизведение и результат

На прежнем условии классификатора два новых сценария Failed при 11 прежних Passed: окно на весь монитор с collect=true не создавало паузу; максимизированное окно с collect=false и панелью задач выше него ошибочно создавало её. Для второго случая фикстура получила независимый факт максимизации, игнорируемый прежним условием. Это проверка поведения модели, без наблюдения настоящего приложения.

После исправления Passed все 19 сценариев scene_registry, включая 8 новых:

| Сценарий | Подтверждение |
| --- | --- |
| Независимость от накопления | При одинаковом полном покрытии collect=false/true дают одну полноэкранную область, а поле накопления в Scene сохраняется |
| Развёрнутое окно с доступной панелью | maximized=true и панель выше него исключают паузу даже при рамке размером с монитор |
| Обычная рабочая область | Окна, оставляющие место снизу, сверху, слева или справа, не признаются fullscreen в обоих режимах collect |
| Матрица доступности панели | Максимизация, видимость, порядок, другая область, нулевое пересечение и полосы активации у четырёх краёв; 20 сочетаний |
| Потеря кандидата | Cloaked-факт, фокус панели, нулевой/отсутствующий foreground и отказ чтения убирают прежнюю область паузы |
| Независимость экранов | Три монитора, отрицательные координаты и 100/150/200%; фоновое окно, перенос foreground, общее покрытие двух экранов и доступная панель только одного |
| Инкрементальное обновление | Смена максимизации читает одно окно и сохраняет поколение; изменение Z-order не читает геометрию остальных |
| Прежний допуск | Полный, увеличенный, 1 px и больший зазор у каждого края; 14 сочетаний для обоих collect |

Полный локальный набор Passed: fmt, clippy -D warnings, 488 тестов клиента и 3 протокола, 5 ignored; release-сборка, 8 повторных release-сценариев снега и 8 smoke модели. Сборщики ресурсов/кадров: 35/31 проверка; JSON Schema: 60; PHP: 60 общих + 5 транспортных, SQLite и HTTP Passed. Модель снега и её отрисовка не изменялись; нагрузочные smoke не являются новой оценкой производительности.

Отдельная release-сборка SHA-256: 68618098DD07F596105711F77FCCDF43214BA002DFB7ED22BD5ABE425901D882. Рабочий EXE не заменялся; read-only status прежнего процесса подтвердил manual и rendering=false. Видимые окна и новый рабочий эффект не запускались.
