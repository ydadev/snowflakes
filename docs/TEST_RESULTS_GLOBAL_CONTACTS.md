# Наблюдаемый вычислитель и нагрузка 16000 пластов

Дата: 14 ноября 2026 года. Windows 11 x64, Rust 1.99.1/MSVC. База — e860d61; решение — [ADR 0059](adr/0059-observed-backend-and-global-contacts.md). Рабочий эффект не включается.

## Проверяемый вход

contact-global использует восемь экранов 200%, 64 принимающих крыши и 16000 активных пластов из действительно закрытых источников. Начальные позы заданы при подготовке, измеряется обычный World::step. По 2000 тел на экран; before проверяет фактические позиции и массу, а after — уменьшение и прирост массы каждой принимающей области. Начальные очереди и масса крыш нулевые. Каждое измерение заново готовит сцену.

contact_evaluator читается из сохранённого Evaluator модели, передаваемого контакту. Метка описывает выбранное семейство функций; portable может использовать библиотечный mul_add на FMA-процессоре. Сведения о CPU-модели/имени узла не собираются. Test-only счётчики отдельно проверяют выполнение функций; release-замер не содержит их накладных расходов.

```powershell
cargo test -p snowflakes-client --lib --locked snow::backend_tests
cargo test -p snowflakes-client --example snow_model_bench --locked
cargo run -p snowflakes-client --release --locked --example snow_model_bench -- --scenario contact-global --steps 60 --warmup 2 --seed 24301
```

Полный tools/check.ps1 Passed: 398 тестов клиента (128 lib, 14 example и прежние интеграционные), 3 protocol, 35 проверок ресурсов, 31 кадров. Прошли fmt/clippy, release, все три smoke модели, Ajv/PHP/SQLite/HTTP. Пять прежних нативных сценариев ignored; IPC/WTS выполнены в обычном Windows-контексте.

Опубликованный код — [b2d10d6](https://github.com/ydadev/snowflakes/commit/b2d10d67a94e0495e03e194af9b9da9cda06df66). [CI 43595712766](https://github.com/ydadev/snowflakes/actions/runs/43595712766) завершился success: Windows — 5 мин 11 с, контракт/PHP — 18 с. Логи подтвердили 398 + 3 теста, все шесть новых сценариев и все три smoke. Глобальный smoke подтвердил 60 свежих эпизодов, восемь полных наборов per_screen и ту же долю полученной массы 0.9919768.

Все три отчёта CI наблюдают fma. Двухэкранный контактный smoke дал среднее 25.344 мс, глобальный — 97.024 мс; каждый из 60 шагов обоих режимов превысил DT. В CI прогрев этих smoke равен нулю. Вычислитель теперь известен на обоих стендах; причину различий времени по одному имени backend не определяем. Прежний CI без поля выбора задним числом не переинтерпретируется.

Перед публикацией проверены 220 файлов, 605 местных ссылок, история, метаданные и удалённые blobs. Рабочие конфиги, копии испытаний, логи и EXE в Git не включены. Отдельная сборка не заменила работающий клиент; read-only статус подтвердил manual/rendering=false.

## Измерение

Прежний и новый замороженные EXE последовательно сравниваются A/B/B/A для трёх старых режимов: baseline 1200/120 шагов, material-stress 360/120, contact-stress 60/2. Затем выполнены два новых contact-global по 60/2 шага. Seed 24301, всего 14 запусков без параллельных компиляций/проверок. [Методика](MODEL_BENCHMARK.md) отделяет подготовку и наблюдение от шага.

| Сценарий | Прежний средний / p95, мс | Новый средний / p95, мс |
| --- | --- | --- |
| baseline | 0.05260 / 0.06275 | 0.05460 / 0.06685 |
| material-stress | 0.52239 / 0.60880 | 0.53224 / 0.60890 |
| contact-stress | 15.36177 / 15.65080 | 15.42541 / 15.58200 |
| contact-global | Не поддерживается | 74.32500 / 116.67070 |

Показаны средние двух запусков и среднее двух p95. Новый выбранный вычислитель — fma во всех режимах. Прежняя сборка не записывала его; по её времени backend не выводится. Ускорение этой диагностической переработки не заявляется. В новом двухэкранном режиме одно из 120 измерений превысило DT; в глобальном — все 120. Подготовка восьмиэкранной сцены и проверка всех областей входят в общее время/CPU процесса.

Три прежних отпечатка совпали: 3646490212806ffa, 2b40f0da0dca0af3, c1b226d3cfc02ba1. Новый глобальный — ebec7a8291d12ead в обоих повторах. Каждый глобальный запуск подтвердил 60 наблюдений, начало с 16000 и уменьшение на 16000. Каждый экран начинал с 2000 и уменьшался на 2000; минимальная доля полученной массы по экрану около 0.9667431, глобальная доля — 0.9919768. Максимальная относительная ошибка глобального баланса — 4.37e-8. Значения около 1 на отдельных экранах допускают округление накопления; отдельный баланс outflow каждого экрана не измеряется.

Наблюдённая сложность входов также отличается: у global 158044 активных ячейки профилей, 9664 ячейки накопления, 72 опоры и 8 падающих масок; у contact-stress — 40814, 2416, 18 и 2. При локализации стоимости нужно учитывать эти размеры вместе с количеством тел.
