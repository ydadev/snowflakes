# Проверки приоритета выпавшего снега

Дата: 13 ноября 2026 года. Среда: Windows 11, Rust 1.99.1/MSVC x64. Область: P3-03/04, SN-06, заполнение экранов и бюджеты частиц. P4 отложен.

Полный tools/check.ps1 Passed: 196 тестов клиента, 3 теста протокола, fmt, clippy с -D warnings, release, JSON Schema, PHP syntax, контракт, SQLite и HTTP. Добавлены семь сценариев snow, усилена прежняя проверка заполненного приостановленного экрана. Всего 92 сценария снега/геометрии.

| Сценарий | Результат |
| --- | --- |
| Резерв обычного снегопада | Сначала Failed: обычная частица занимала место сверх 2272 и съедала резерв. После исправления Passed: оба экрана принимают собственные 2272 обычные частицы и сохраняют место для материала |
| Два заполненных экрана | Passed: закрытие опор при полном обычном снегопаде выпускает пласты активного экрана в первый физический шаг; приостановленные частицы сохраняют поля. После возобновления второго экрана выпускается его материал |
| Перенос ветром и заимствование | Passed: переход всех обычных частиц на один экран не удаляет их и не мешает резерву материала. При последующем заполнении пластами один экран не занимает чужой незаполненный резерв; общий допуск остаётся ограничен |
| Заполнение самим материалом | Passed: когда и резерв, и остальные места заняты, следующая масса сохраняется в очереди. После приземления предыдущих тел очередь выпускается и обе порции образуют горки |
| Начальное заполнение | Passed: два синтетических экрана 3840 × 2160 получают по 1600 снежинок; второй не ограничивается остатком прежнего общего бюджета |
| Уменьшение состава экранов | Passed: изменение цели допуска не удаляет существующую массу. После естественного выхода частиц за выбранную сцену счётчики освобождают место. Clear сбрасывает очереди и счётчики |
| FPS, пауза и сцена | Passed: при 30/60 FPS, синтетических 100/200%, паузе и периодических снимках совпадают положения, скорости, масса и очередь |
| Прежняя заполненная пауза | Passed: 2272 обычные частицы приостановленного экрана больше не заставляют 240 закрытий другого экрана ждать; 128 укрупнённых записей начинают падение в следующий шаг и образуют горки |

Для начального резерва проверено именно движение после первого вызова World::step, не только появление записи в памяти. Проверка полного материального бюджета сохраняет ожидание и баланс вместо удаления массы. Прежние сценарии масок, оседания, укрупнения, кромок, смахивания и 30/60 FPS прошли.

Not run: задержка на реальном рабочем столе, путь ввод → сохранение → кадр за 200 мс, нативные переходы экранов/DPI, Windows 10, CPU/GPU/память и длительный прогон. При непрерывной перегрузке самими пластами универсальный срок ожидания не принят. Временное превышение локальной доли после миграции или новой общей цели после отключения экрана не устраняется удалением живого материала. Рабочий эффект для этого этапа не запускался.
