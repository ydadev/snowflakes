# Проверка регулятора сугробов через профиль и GPU

Дата: 15 ноября 2026 года. Среда: Windows 11, Rust 1.99.1/MSVC x64. Область: P2-01/03, P3-02/04, CT-06/07. Активна разработка снега; вода, сайт и поставка отложены.

## Стенд и проверяемая цепочка

Переиспользован [мост скрытой панели](TEST_RESULTS_NATIVE_CONTROL_BRIDGE.md): настоящие Panel, Owner/Controller, временный UserStore и опубликованный View. Нативный ползунок размера сугроба получает TBM_SETPOS/WM_HSCROLL только после проверки владельца, скрытого состояния и PMv2. Каждая команда проходит настоящую очередь управления и атомарное сохранение TOML; файл сравнивается с View. Нижний Weather::update/GPU работает на другом потоке, ждёт настоящий WM_NULL от Owner и сверяет токен/настройки публикации. Дополнительные шаги времени не создают фиктивных команд или пробуждений.

Сцена начинается с нулевой массы. NativeTestHost создаёт собственные окна на невходном startup desktop и расширяет одну крышу штатной командой SWP_NOACTIVATE. Настоящие Native/Tracker определяют опору; единственный источник материала — обычный производственный emitter. Начальные профили, тела, очередь и ledger тестом не задаются. После интенсивности 0 все летящие тела и очередь ожидаются с прежними силами в пределах 7200 STEP.

Сохранены прежние guards имени/UOI_IO, PID/TID, PMv2, NoActivate, Watchdog и Job Object. Профиль и отсутствующий источник политики изолированы. Ручная пауза не снимается; Conditions остаются неготовыми, Observer/Worker не создаются. Это прямой нижний компонентный путь, а не активный полный Worker.

## Поведение

| Проверка | Критерий |
| --- | --- |
| Естественный запас | Начальные масса и introduced_mass равны нулю; снегопад наполняет настоящую крышу, после выключения интенсивности весь воздух/очередь освобождаются |
| Снижение 100 → 1% без шага | Все mass/pending-профили, introduced/removed и полный GPU bitmap совпадают с прежними; мгновенного обрезания нет |
| Плавное уменьшение | Первый STEP сохраняет более 80% избытка; через одну модельную секунду остаётся 20–80%; после 2,5 секунды избыток всех опор меньше 0,001 единицы массы |
| Нижняя и оконная опоры | До перехода обе имеют положительный избыток; независимый f64-расчёт ёмкости использует пределы 120/32 DIP, 1% и настоящее headroom при неизменном DPI |
| Рост 1 → 100% без шага | Снова совпадают все профили, учтённая масса и bitmap; увеличение предела не раздувает снег |
| Две секунды без осадков | introduced_mass неизменна, тел/очереди нет, суммарная масса сохраняется с допуском 0,001; нового запаса нет |
| Новые осадки | Крыша получает новую массу и большую alpha только после нового снегопада; прирост крыши меньше всей новой введённой массы |
| Завершение | Сохранены HWND/эпоха слоя; настоящий Host, поток управления и GPU завершаются, Layer уничтожен, Job не содержит активных процессов |

Снимок берётся после настоящего render_snow/EndDraw, до Present; отдельной перерисовки для проверки нет. Исходные bitmap и профили используются только в памяти, в Git публикуются числовые результаты. Допуск 0,001 у f64-оракула учитывает накопленное f32-округление.

## Результаты

Отдельные debug и итоговый release Passed. В release настоящий снегопад за 148 STEP достиг порога крыши; после интенсивности 0 воздух/очередь освободились ещё за 2635 STEP. Крыша содержала около 536,087 единицы массы, пик достигал 6,789 физического пикселя на DPI=96. Уменьшение предела не изменило нулевой кадр: суммарный избыток всех опор составлял 1712,129, из него 427,197 на проверяемой крыше и 1091,777 на полу.

| Момент после уменьшения | Суммарный избыток | Масса крыши | Пик крыши | Сумма alpha в полосе крыши |
| --- | --- | --- | --- | --- |
| Без шага | 1712,129280 | 536,086515 | 6,788642 | 76094 |
| Первый STEP | 1697,861544 | 532,526542 | 6,734736 | 75200 |
| 1 с, всего 60 STEP | 856,065134 | 322,488307 | 3,554323 | 26912 |
| 2,5 с, всего 150 STEP | 0,000060 | 108,889891 | 0,32 | 879 |

Возврат 1→100% в тот же момент сохранил все профили и полный bitmap. За последующие 120 STEP без осадков крыша и alpha остались прежними, общая масса изменилась менее чем на 0,000001 от округления. Следующий снегопад ввёл ещё около 3516,801 единицы массы; после полного оседания крыша содержала 766,975, alpha выросла до 119813. Новый материал не приписывается самому регулятору. Длительности наполнения зависят от исходного потока; это измеренный прогон, а не эталон фиксированного числа частиц.

Прошли семь настоящих команд/сохранений и семь пробуждений GPU: ключи 3,1,1,3,3,1,1. Трасса: input/dispatch/received/applied=7, superseded=6, rejected/dropped=0, observed/submitted=0, unfinished=1. Замены предыдущего токена и последний незавершённый токен сохраняют прежнюю семантику; нижний стенд не выдаёт себя за полный Worker. Все 5965 Present дали OCCLUDED, S_OK не было. Максимальная относительная ошибка баланса около 5,70e-7. Все принадлежащие сценарию потоки/процессы завершились штатно.

Полный tools/check.ps1 Passed: fmt/clippy, 515 тестов клиента, 3 протокола и 8 release-повторов — 526 выполнений, 32 ignored. Восемь smoke сохранили эталонные отпечатки и ограничения массы/пулов. Сборщики 35/31, JSON Schema 60, PHP 60+5, SQLite и HTTP проверили прежние компоненты; вода/сайт не разрабатывались. Прежний отдельный release-мост размера/заметности и отказа записи также Passed. Две новые аппаратные точки исключены из обычного набора. GitHub CI опубликованного исходника ожидается.

Производственные ветви, силы, фильтры и сроки перехода не изменялись; новые средства ограничены cfg(test). SHA-256 собранного release EXE: A293742BD0ECFD8DB0B0312B262F18C8F76FA78A15CC99CD053EF72E288608DA. Побайтное равенство прежней сборке не заявляется. Read-only статус рабочего клиента подтвердил manual/rendering=false.

## Границы результата

Not run: настоящий ввод и показанный переход, активный Worker, CT-10 за 200 мс, Windows 10, mixed DPI, hotplug, device loss и ресурсы всего клиента/длительный прогон. Модельное время не равно wall-производительности. OCCLUDED не принимается за S_OK или доказательство видимого кадра. Реальные системные паузы не подменялись.

Рабочий эффект не включался, клиент не заменялся, input desktop не переключался. Дождь и лужи не разрабатывались. Общая цель и этапы P2/P3 остаются активными.
