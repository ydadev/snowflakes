# Нативный выбор экрана и жизненный цикл GPU-слоёв

Продолжение: [подготовка переноса естественного запаса](TEST_RESULTS_MONITOR_TRANSFER_PREPARATION.md) разделяет успешный preflight и Not run при отсутствии настоящего secondary. Положительный двухмониторный перенос остаётся открытым.

Дата: 15 ноября 2026 года. Клиент 0.1.0, Rust 1.99.1/MSVC, Windows x64. Область: часть P1-04/P2-02, выбор дисплеев и владение ресурсами. Продолжает [Worker-пробу](TEST_RESULTS_PRIVATE_WORKER.md) и [ADR 0081](adr/0081-private-desktop-worker-probe.md). Исходник: [monitors.rs](../crates/snowflakes-client/src/platform/worker_probe/monitors.rs).

## Проверенный путь

Отдельный библиотечный тестовый процесс запускается с заданным STARTUPINFOW.lpDesktop. Имя и UOI_IO=false проверяются до работы; переключение desktop и активация не запрашиваются. Общий launcher ограничивает время ребёнка 30 секундами и завершает только свой process handle при отказе. Рабочий клиент, IPC, трей, настройки пользователя и сеть не участвуют.

Сценарий вызывает настоящий Weather::update с Native/Tracker, World и Layer/Gpu после входа потока в PMv2. EnumDisplayMonitors/GetMonitorInfoW отдельно задают ожидаемые физические рамки и основной монитор. Снимки Source и геометрия не подставляются; снег первоначально появляется через seed_air. Observer-гейт полного Worker здесь не вызывается. Его настоящие системные паузы остаются проверкой исходной пробы, активный цикл Worker не засчитывается.

В каждой подтверждённой сцене сверяются HWND/PID/поток/PMv2, производственные стили, GetWindowRect/GetClientRect, размер Direct2D bitmap и DXGI swap chain, DPI от HWND, scale слоя и World.scene. При удержании слоя сравниваются HWND, raw-идентичность swap chain и эпоха слоя без сохранения лишней COM-ссылки. Удалённые HWND проверяются через IsWindow, после возврата требуются новые эпохи слоёв.

## Результат release-прогона

Windows предоставила **один** монитор, DPI=96. Рамки/буферы/scale совпали на всех шести этапах; состояние графики осталось без ошибки.

| Этап | Слоёв | Подтверждение |
| --- | --- | --- |
| Все | 1 | Настоящий Native-снимок, слой и начальный снег World |
| Основной | 1 | Прежние HWND, swap chain и эпоха сохранены |
| Выбранный доступный | 1 | Выбран тот же единственный монитор; отдельный второй недоступен для проверки |
| Выбранный без изменения | 1 | Ресурсы удержаны, новое окно не создаётся |
| Выбранный недоступный | 0 | Слой и экран World удалены, прежний HWND уничтожен, часы сброшены |
| Возврат ко всем | 1 | ID экрана сохранён, слой создан в новой эпохе; окончательный Drop уничтожил HWND |

Пять настоящих Present вернули 0x087A0001 (DXGI_STATUS_OCCLUDED). Каждый исходный код записан test-only ограниченной трассой; возвращаемое число принятых кадров и приращения S_OK-счётчиков равны нулю. У недоступного выбора Present отсутствует. Это не доказательство показанного кадра или FPS.

distinct_secondary=false и exclusions_destroyed=false: исключение одного доступного монитора при сохранении другого **Not run**. Пустой выбор и последующее восстановление действительно проверены. Успешное выполнение одноэкранной ветви не закрывает многомониторную приёмку.

Первый вариант стенда ошибочно ожидал готовую сцену сразу после изменения выбора. Registry объединяет изменения в течение 30 мс; тест теперь обрабатывает настоящую очередь сообщений и ждёт готовности не более 3 секунд. Во время ожиданий проверяются скрытие прежних слоёв, отсутствие Present, неизменность их ресурсов/счётчиков и сохранённое состояние графики без ошибки. В release-прогоне наблюдались 3/3/2 ожидающие итерации на selected/unavailable/all_restored; это диагностические количества, а не замер задержки или FPS. Фильтры, объединение событий и сроки производственного кода не менялись.

Полный локальный набор Passed: fmt/clippy, 515 тестов клиента, 3 протокола и 8 release-повторов — 526 выполнений, 10 ignored; восемь smoke сохранили отпечатки и прошли ограничения массы/пулов. Сборщики 35/31, JSON Schema 60, PHP 60+5, SQLite и HTTP прошли как проверка прежних компонентов. Отложенная разработка сайта не возобновлялась. Отдельно прошли новый release-сценарий и прежняя Worker-проба после извлечения общего launcher/DPI scope; оба ребёнка завершились штатно.

Коммит 058b6e4 прошёл [GitHub CI](https://github.com/ydadev/snowflakes/actions/runs/43685760768): оба задания success. Декодированный Windows-журнал подтвердил 526 выполнений, 10 ignored, все восемь эталонных отпечатков smoke и ограничения массы/пулов; сборщики 35/31 прошли в PowerShell 7 и Windows PowerShell. Отдельное задание подтвердило JSON Schema 60, PHP 60+5, SQLite и HTTP. Обе новые аппаратные точки и исходная Worker-проба действительно исключены из обычного CI. Одноэкранная аппаратная проверка выше выполнена отдельно локально, её результат не подменяется зелёным CI.

Изменения только в test-only стенде. Release EXE побайтно совпал с предыдущей сборкой: SHA-256 D4071529E045B43F5D25C0A0AB8C6FFDF4CC3C11CFD13F08EE1D3FCD3D2CBA3A. Рабочий эффект не заменялся и не возобновлялся.

## Повторение и ограничения

~~~powershell
cargo test -p snowflakes-client --release --locked --lib platform::weather::worker_probe::monitors::native_monitor_selection_preserves_retained_layers_and_releases_excluded_layers -- --ignored --exact --nocapture --test-threads=1
.\tools\check.ps1
~~~

Строка native_monitor_layers содержит количество доступных мониторов, результаты фаз и исходные коды. Проверять distinct_secondary перед выводом о втором мониторе. Физические настройки дисплеев не изменяются; разных DPI и hotplug в сценарии нет. Реальные ID/координаты дисплеев в отчёт не выводятся.

Not run: второй доступный монитор и сохранение одного при исключении другого, mixed DPI/WM_DPICHANGED, настоящий hotplug, активный Worker/S_OK, видимый вывод, настоящий ввод, device loss, ресурсы всего клиента, длительная устойчивость и полная матрица Windows 10/11. P1/P2/P3 остаются In progress; вода, сайт и поставка отложены.

Основания API: [EnumDisplayMonitors](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaymonitors), [GetWindowRect и DPI](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect), [GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow).
