# Таяние через сохранённую настройку и GPU

Дата: 15 ноября 2026 года. Область: P3/SN-08 и часть CT-08. Windows 11 x64, основной монитор DPI=96, D3D11/Direct2D/DirectComposition на собственном невходном desktop.

## Изменение

Малое вычитание таяния из ячейки `f32` округляется. Прежний счётчик суммировал запрошенное удаление, поэтому на длинном интервале расходился с действительным запасом. Теперь removed_mass получает разность значений до/после вычитания в `f64`. Скорость 0,002 DIP/с, силы, порядок шага и геометрия сохраняются. [ADR 0082](adr/0082-melting-mass-accounting.md).

Минутная регрессия равномерного слоя Failed до исправления, Passed после: баланс проверяется каждую модельную секунду с допуском 1e-9, интеграл прежней скорости — независимо с допуском дискретизации `f32`. После снятия флага ещё 600 STEP сохраняют массу и выход точно. Этот модельный тест использует явно заданный запас; аппаратный сценарий ниже получает снег только обычным emitter.

## Связанный сценарий

Из пустой сцены обычный снегопад наполняет настоящую крышу. Собственные скрытые checkbox/ползунки передают команды реальному Owner/Controller: временный TOML сверяется с опубликованным View, отдельный графический поток читает именно View после настоящего пробуждения. Новый test-only доступ ограничен SnowMelting, ключом 25 и прежними проверками владельца, потока, parent, hidden, enabled и PMv2.

При положительном воздухе галочка включается/выключается без физического шага; все остальные Settings, профили, текущие физические поля частиц и ledger сохраняются точно. Восемь повторных кадров с неизменными настройками отдельно измеряют малую вариацию нативного растра. При сравнении изображения допускаются не более восьми разных пикселей и максимум 16 уровней канала; записываются фактические числа. Точность bitmap не подменяет точность физических полей.

Затем интенсивность 0 прекращает приток, прежние частицы естественно оседают, воздух/очередь должны опустеть. Два включения таяния по 1200 STEP уменьшают массу и alpha обеих опор, выход согласуется с потерей в пределах ошибок двух отдельных ledger. Между периодами снятая галочка на 120 STEP сохраняет removed_mass точно, массу — в пределах 0,001. Нового снега и подставного запаса нет. Модельное время не принимается за wall-время.

Из восьми кадров без изменения настроек два различались одним пикселем на один уровень канала; debug также выявил единичную вариацию до 11 уровней, при точной физике. Поэтому общий узкий допуск задан явно, побайтная идентичность для всех прогонов не заявляется. После интенсивности 0 приток не менялся, воздух/очередь пусты.
