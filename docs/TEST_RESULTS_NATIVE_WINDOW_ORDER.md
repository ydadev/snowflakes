# Проверка нативного порядка окон

Дата: 15 ноября 2026 года. Клиент 0.1.0, Rust 1.99.1/MSVC, Windows x64. Область: P2-02/04, GE-02, OS-02/03/06. [Решение](adr/0078-validated-native-window-order.md).

## Проверки поведения

Добавлено 11 тестов: 9 библиотечных и 2 сценария scene_registry.

| Область | Подтверждение |
| --- | --- |
| Явный порядок | Четыре разные цепочки при перемешанном инвентаре дают порядок связей, а не перечисления |
| Членство и идентичность | Исчезнувшие, повторно использованные и новые не перечисленные HWND; живой пропущенный узел; изменение PID во время обоих проходов; отсутствие доступной идентичности |
| Несогласованность и ошибки | Изменение связей во время сбора/проверки, ошибка API, дубликаты и неверный инвентарь отвергаются |
| Конечная работа | Самоссылка/цикл, границы 511/512/513, цикл на хвосте 512, пустой допустимый префикс; проверяются пределы числа запросов |
| Нативный Rust adapter | Три собственных скрытых окна, 12 перестановок обычной/topmost групп и 2 смешанных случая проходят через настоящий Native::order; проверены скрытость, принадлежность и очистка |
| Поколения Registry | Замена PID без destroy читает только заменённое окно и меняет его ключ; замена между порядком и геометрией исключает поверхность |
| Ожидание Tracker | Ошибка порядка и ошибка дисплеев не выходят как ошибка GPU; до 100 мс источник не опрашивается, затем восстанавливается начальная/сохранённая сцена и прежний ключ |
| Ожидание Weather | Без создания слоёв/GPU: снег сохраняется, шаги и история курсора не накапливаются, бюджет graphics recovery и время следующего опроса проверены |

Сначала Passed 5 тестов ядра и отдельная нативная проверка. Два полных локальных прогона Passed; окончательный включает обработку ошибки дисплеев, расписание ожидания и крайние случаи бюджета. Результат: 499 тестов клиента, 3 протокола, 5 ignored; fmt/clippy, release-сборка, 8 повторных release-тестов снега и 8 smoke модели. Сборщики: 35/31 проверка; JSON Schema: 60; PHP: 60 общих + 5 транспортных, SQLite и HTTP Passed.

Отдельная release-сборка SHA-256: D46018C1D83E6588B48EBC897A6DE18E1626130F1895EDB03CF0E717214D0C7C. Рабочий EXE не заменялся; read-only status прежнего процесса подтвердил manual и rendering=false. Физические силы и отрисовка снега не менялись; изменён только допуск обновления/вывода при ожидании сцены. Smoke не дают приёмку производительности всего клиента.

[CI исходников 01bffdf](https://github.com/ydadev/snowflakes/actions/runs/43668672584) завершился success в обеих задачах. Декодированные Windows-журналы подтвердили все 11 новых сценариев, включая нативный Rust adapter: 499 тестов клиента, 3 протокола и 8 повторных release-тестов; всего 510 выполнений Rust, 5 ignored. Восемь smoke сохранили прежние отпечатки и проверку массы/пула; hidden-stream — 48d108fc3385cf1a в обоих режимах. Продуктовая приёмка производительности остаётся Not run. Сборщики прошли PowerShell 7/5.1, контракт/PHP/SQLite/HTTP Passed.

Нативные окна не имели WS_VISIBLE, перемещались в Z-order с NOACTIVATE и уничтожались в своём потоке после проверки PID/потока. Чужие окна не изменялись; заголовки, изображения и содержимое не читались. Сбор порядка запрашивал только HWND/PID/поток/связи. Рабочий эффект не запускался.

## Повторение и предел доказательства

~~~powershell
cargo test -p snowflakes-client --locked --lib window_order::tests
cargo test -p snowflakes-client --locked --lib native_order_revalidates
cargo test -p snowflakes-client --locked --test scene_registry
.\tools\check.ps1
~~~

В отличие от предыдущей отдельной P/Invoke-пробы, новый нативный тест вызывает производственный Rust Source. Он не доказывает атомарность снимка, приёмку всех классов окон и обеих ОС. Ограничение числа запросов не является измерением стоимости Win32 или гарантией времени кадра. Сохранение настоящих GPU-ресурсов при потере сцены и возврат видимого кадра здесь не подтверждены тестом без GPU.

Not run: матрица Windows 10/11 с реальными fullscreen/Shell/автоскрытием, длительная конкурентная смена состава окон, рабочие столы/сеансы, фактический device lost, ввод, CPU/GPU/память полного клиента и длительный прогон. Для этих условий нужен разрешённый нативный стенд. P2 и проект остаются In progress; снег — текущий приоритет, вода/сайт/развёртывание отложены.
