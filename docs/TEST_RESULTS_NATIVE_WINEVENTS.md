# Межпроцессные WinEvent и пустая сцена

Дата: 15 ноября 2026 года. Клиент 0.1.0, Rust 1.99.1/MSVC, Windows x64. Область: P2-02/04, OS-02/03. [Решение](adr/0080-native-winevents-and-empty-scene.md).

## Воспроизведение пустого снимка

На новом изолированном desktop без окон EnumWindows вернул FALSE, callback не был вызван, LastError=0. GetTopWindow также подтвердил отсутствие головы без ошибки. Прежний производственный Native::order отклонил этот снимок с ERROR_RETRY; отдельный регрессионный тест Failed до исправления.

Теперь такой результат требует подтверждения NULL во всех запросах головы проверяемого обхода. Старый LastError очищается перед перечислением. Ошибки с ненулевым кодом, непустой частичный инвентарь и наблюдённая живая голова не получают разрешения пустой сцены. Остальные ограничения прежнего сборщика сохраняются.

## Нативные сценарии

Добавлены два библиотечных теста и служебная ignored-точка входа дочернего тестового процесса. Она вызывается родительскими сценариями с --exact/--ignored; это не пропущенная продуктовая проверка. Родители проверяют нормальный код завершения трёх дочерних запусков.

| Проверка | Подтверждение |
| --- | --- |
| Пустой desktop | Нулевой снимок при заранее установленном ERROR_ACCESS_DENIED; два цикла создания и нормального завершения дочернего процесса с возвратом к пустому порядку |
| Создание | Настоящие события двух скрытых окон принимаются производственным callback и добавляют опоры до резервной сверки |
| Серия движений | 32 вызова SetWindowPos меняют первое окно; в 29 мс после принятой сцены чтений нет, в 30 мс выполняется одно чтение первого окна, второе сохраняет геометрию/поколение |
| Z-порядок | Настоящая перестановка окна вызывает один запрос порядка без чтения стабильной геометрии |
| Закрытие | Уничтоженная опора удаляется, ключ второго окна сохраняется |
| Свой процесс | Создание/перемещение/уничтожение окна родителя не вызывает обновления Registry в контрольном окне наблюдения |
| Drop Tracker | После снятия hooks ребёнок действительно меняет оставшееся окно; новых изменений в Registry не появляется в контрольном окне наблюдения |

Целевой прогон Passed: два нативных сценария; служебная точка входа ignored в родительском запуске и выполнена в дочерних процессах. Полный локальный набор Passed: 505 тестов клиента, 3 протокола и 8 повторных release-тестов снега — 516 выполнений во внешних Rust-результатах; 6 ignored, включая служебную точку. fmt/clippy, release-сборка и восемь smoke Passed; отпечатки модели, масса и ограничения пула сохранены. Сборщики: 35/31; JSON Schema: 60; PHP: 60 общих + 5 транспортных, SQLite и HTTP Passed. Это проверка регрессий существующих компонентов, работа над водой/сайтом не возобновлялась.

Локальный Windows build — 26200. Отдельный EXE SHA-256: 41350D23418487B859A393B3FB7C8285C38C160356C9C5F69C9FEE5813E05200; рабочий клиент не заменялся. Read-only status подтвердил manual и rendering=false.

[CI исходников 22c73bd](https://github.com/ydadev/snowflakes/actions/runs/43672936122) завершился success в обеих задачах. Windows-журнал подтвердил оба новых нативных сценария и прежние проверки порядка/повторной сверки. Итог: 505 тестов клиента, 3 протокола и 8 повторных release-тестов, 516 выполнений во внешних результатах, 6 ignored. Восемь smoke сохранили отпечатки и проверку массы/пула; сборщики Passed в PowerShell 7/5.1. Контракт/PHP/SQLite/HTTP Passed. Windows runner настроен на windows-2022; это не приёмка обеих целевых ОС.

## Повторение и ограничения

~~~powershell
cargo test -p snowflakes-client --locked --lib platform::scene::tests::events:: -- --nocapture
.\tools\check.ps1
~~~

Производственные Tracker::new, подписки, callback, Registry и Native::order выполняются по-настоящему. Тест сам обрабатывает очередь Windows и переносит накопленные Changes в реестр тем же способом, что Tracker::poll; Native::read заменён ограниченным Source для скрытых опор. Это не полный путь рабочего графического потока. Периодическое обновление исключено управляемым временем 0–180 мс; очередь обрабатывается отдельными циклами с ожиданием по 150 мс. Эти интервалы не являются измерением задержки продукта.

SwitchDesktop, ShowWindow, прямой вызов callback и NotifyWinEvent в тестах не используются. Чужие окна не изменяются; содержимое, заголовки и изображения не считываются. Рабочий эффект не запускается.

Not run: реальные видимые окна и ввод, show/hide, минимизация, cloaking, смена входного desktop, соединение нативных событий с массой снега/пластами, фактический возврат GPU-кадра, полная матрица Windows 10/11, ресурсы всего клиента и длительный прогон. P2/P3 остаются In progress. Разработка дождя и луж отложена.
