## Независимые условия

Первый тест выполняет все четыре сочетания успеха/отказа. Callback проверяет точные GUID и порядок двух попыток; непрозрачные u32 проверяют сохранность обязательного префикса и только успешных результатов. Эти значения не являются подставными HWND/HPOWERNOTIFY и не передаются Windows. Настоящий Recorder подтверждает раздельные fault/HRESULT, отсутствие сообщения/пути и ленивую историю при успехе.

Второй тест после отказа обоих GUID вызывает настоящий общий Poll с управляемыми запросами, с привязанным журналом и без него. Готовность восстанавливается по снимку сеанса; чтение питания меняет low_power при первом и пятом секундном сроке, до срока callback не вызывается. Ревизия симуляции, профиль и Manual сохраняются, should_render остаётся false. Последующие успешные запросы не стирают две записи регистрации. Отсутствие журнала не меняет результаты.

Новые адресные тесты не создают окон/настоящих регистраций, не читают ввод и не меняют питание Windows. Нативный успешный конструктор и скрытые уведомления проверяются прежним отдельным тестом; управляемый callback не доказывает реальный отказ API или очистку частичного нативного набора.

## Ограничения и повторение

Настоящие отказы уведомлений, lock/sleep/RDP/батарея, активный полный Worker, видимый вывод, mixed DPI/второй монитор, ресурсы и Windows 10/11 целиком **Not run**. Пять секунд здесь заданы Instant, не wall-замером. Публичный отчёт не содержит частных параметров среды. Вода, сайт и поставка отложены; P1/P2/P3 и общий проект не объявляются завершёнными.

~~~text
cargo test -p snowflakes-client --lib --locked quality_notification_journal
cargo test -p snowflakes-client --release --lib --locked quality_notification_journal
~~~

Общий набор: ./tools/check.ps1. Рабочий клиент не включается и не заменяется.
