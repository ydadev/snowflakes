# ADR 0002 Полный погодный профиль

Статус: принято. Дата: 13 ноября 2026 года.

Расширение до v2 с процентными настройками снежинок зафиксировано в [ADR 0008](0008-physical-snow-and-appearance.md). Ниже — исходное решение v1.

## Решение

Ответ назначения версии 1 содержит метаданные поколения/ревизии и весь объект settings. Неполные и неизвестные поля отклоняются атомарно. Настройки подключения, токены и выбор местного/серверного управления не входят в погодный профиль.

Четыре процента интенсивности и накопления независимы. В settings присутствуют оба режима, даже когда один неактивен. effective_effects_enabled вычисляется как global_enabled AND settings.effects_enabled.

display.selection принимает all, primary или selected. Список monitor_ids разрешён только для selected и содержит до 16 устойчивых идентификаторов. Доступность выбранных устройств проверяется при применении, отдельно от проверки схемы. Эта форма заменяет неоднозначное сочетание all_monitors со специальным идентификатором основного экрана.

## Проверка

Схема JSON, Rust и PHP проходят 50 общих случаев: пределы, типы, обязательные/неизвестные поля и выбор экранов. Rust/PHP дополнительно отклоняют повторные ключи и дробные токены целых полей. Предел документа — 64 КиБ; ревизия ограничена безопасным целым JSON.

Пример по умолчанию не содержит реквизитов. Версия локального TOML не связана с schema_version API.

## Последствия

Для изменения контракта нужны согласованные исходники, схема и примеры. Регистрация, sync и ack получат собственные схемы до появления публичных клиентских маршрутов. Node/Ajv остаются инструментами разработки; PHP-поставке они не нужны.
