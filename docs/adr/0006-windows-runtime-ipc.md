# ADR 0006 Windows runtime и локальный IPC

Статус: принято для основы P2. Дата: 13 ноября 2026 года.

## Владение

Поток управления владеет Controller, Session, UserStore и выполняет запись предпочтений. GUI-поток владеет HWND, HICON и состоянием трея через Rc/Cell. Он читает снимки статуса; дисковая запись и IPC не выполняются внутри callback меню. Это продолжает правило единственного владельца Session из ADR 0004.

Работник IPC принимает только типизированные Command и передаёт их в ограниченную очередь из восьми элементов с отдельным каналом ответа. Просроченная команда в очереди не применяется. Поток управления продолжает отвечать, когда GUI обрабатывает контекстное меню.

## Экземпляр и канал

Mutex Local и именованный канал включают SID владельца и Session ID. В release дополнительного пространства имён нет. Mutex удерживается до завершения процесса; оставленный mutex разрешает восстановление после окончания владеющего потока.

Канал имеет явный DACL: владелец, локальные администраторы и SYSTEM. Используются FILE_FLAG_FIRST_PIPE_INSTANCE и PIPE_REJECT_REMOTE_CLIENTS. Клиент проверяет SID и Session ID процесса сервера до отправки команды и ограничивает impersonation режимом identification.

JSON-запрос IPC имеет schema_version=1 и вложенную command. Неизвестные версии, поля, команды и типы отклоняются. Команды без параметров представлены пустыми struct-вариантами: это позволяет serde отвергать лишние поля, которые unit-вариант мог бы пропустить. Сообщение ограничено 64 КиБ.

Чтение/запись выполняются overlapped с тайм-аутом; pending-операция отменяется и завершается до освобождения OVERLAPPED, события и буфера. Короткое подтверждение клиента с ограниченным ожиданием заменяет неограниченный FlushFileBuffers. Состояние GUI не передаётся работнику через указатели.

## Запуск и завершение

Обычный запуск связывает UserStore с Session и добавляет оригинальную процедурную иконку в трей. Повторный ensure не создаёт вторую Session и не снимает паузу. Обычный GUI запрещён в Session 0 или невидимой window station; CLI-контроль не требует создания GUI. Release использует Windows subsystem, сохраняет перенаправленный stdout и при необходимости подключает консоль родителя для CLI.

Enabled и ограничения читаются из 64-битного HKLM Software/Policies/Snowflakes при запуске и резервно через 60 секунд. Ошибка чтения закрывает процесс. Уведомление реестра, реальные события блокировки/сна и полный доменный пилот ещё впереди.

Выход и запрет политики создают marker текущего входа. from-logon его соблюдает, явный Start снимает. Ошибка записи marker не удерживает процесс против команды выхода и сообщается CLI. Очистка marker прошлых входов и проверка новых входов/перезагрузок остаются P6/P7.

## Трей и границы

Есть снег/дождь, ручная пауза, очистка, галочка источника и выход. Изменения проходят Controller с проверкой сохранения до применения. Ошибки показываются немодальным уведомлением. При выходе управление посылает WM_CANCELMODE, чтобы открытое меню не удерживало завершение. Получение TaskbarCreated запрашивает восстановление значка.

Компактная панель с четырьмя регуляторами и адресом добавлена в [ADR 0007](0007-native-settings-panel.md). GPU и HTTP не подключены; status явно отличает желаемые эффекты от rendering=false. Адресация другого пользовательского сеанса и тесты всех ACL-принципалов остаются отдельными задачами.

## Подтверждение

Пройдены пять тестов Controller, три теста Win32 IPC/ACL/mutex и один тест дочернего процесса с несколькими запусками. Обычные debug и release процессы успешно создали трей через Shell API, отвечали CLI и завершились. Визуальная проверка и клики по меню не засчитаны.
