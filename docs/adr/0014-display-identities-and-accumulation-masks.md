# ADR 0014 Идентификаторы мониторов и маски накопления

Статус: принято для P2-02/P3-04. Дата: 13 ноября 2026 года.

## Причина

Идентификатор выбранного монитора вычислялся из HMONITOR — временного дескриптора. Перекрытие учитывало только горизонтальную линию опоры. Поэтому окно, закрывающее верх сугроба, но заканчивающееся выше опоры, не скрывало этот снег. Нижняя опора не имела маски меню.

## Идентификаторы

MONITORINFOEXW предоставляет имя устройства GDI; EnumDisplayDevicesW с EDD_GET_DEVICE_INTERFACE_NAME возвращает пути интерфейсов активных мониторов. Это документированные API: [MONITORINFOEXW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-monitorinfoexw), [EnumDisplayDevicesW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaydevicesw).

Нормализованные пути сортируются, повторения удаляются. Их детерминированный FNV-1a хеш с доменом monitor-interface-v1 образует локальный display-ID. Старший бит зарезервирован для нижней опоры. Смена номера GDI, порядка перечисления или HMONITOR не входит в расчёт. При отсутствии пути применяется отдельный домен monitor-gdi-v1 с именем GDI; обнаружение явно сообщает persistent=false.

Raw-пути используются только внутри обнаружения; в вывод попадают ID и геометрия. Хеш не служит секретом или криптографическим идентификатором. Идентичность зависит от экземпляра устройства Windows: иной порт, док-станция или драйвер могут изменить путь. Между компьютерами ID не переносятся.

Команда --list-monitors --json выполняет только обнаружение в собственном процессе с координатами физических пикселей. Она не создаёт владельца IPC, не открывает панель, не меняет профиль и не снимает паузу. Для ранних конфигураций selection=selected требуется заново выбрать ID: достоверного соответствия прежнему HMONITOR после его исчезновения нет. Режимы all/primary сохраняют поведение.

## Перекрытие

Для каждой опоры кешируются непересекающиеся прямоугольники доступной области над ней. Оконную опору закрывают видимые окна перед ней. Нижнюю опору закрывают видимые поверхности, не принимающие снег: меню, подсказки и другие подобные окна; прежнее отображение нижнего сугроба поверх обычных приложений сохраняется. Это не заменяет проверку распознавания настоящих системных панелей на каждой ОС.

Горизонтальные границы перекрывающих окон разбивают область на вертикальные полосы. В каждой полосе вычисляются максимальные свободные интервалы по высоте. Такое представление не создаёт ложного ограничения высоты рядом с перекрытием. Глубина области — 140 физических пикселей для окна и 490 для нижней опоры, с запасом относительно пределов 32/120 DIP при максимальном поддерживаемом масштабе 4.

Рендерер строит профиль сугроба один раз и рисует его через маску. Границы полос не сглаживаются, чтобы не образовывать швы; сглаживание контура снега сохраняется. Контакт осадков, распределение новой массы и курсор используют ту же доступную область. Новая масса ограничена свободной высотой до перекрытия. Скрытие уже накопленной массы не удаляет её; прежние таяние, оседание и явная очистка сохраняются.

Бюджет — 2048 прямоугольников на опору. При превышении опора временно не рисуется и не принимает осадки, сохраняя массу. Это ограничение геометрии, не подтверждение бюджета CPU/GPU.

## Проверки и границы

Два теста идентичности проверяют нормализацию, перестановку, разные устройства, fallback и закреплённый результат хеша. Шесть сценариев снега проверяют верх сугроба, порядок окон, маски нижней опоры, отрицательные координаты, отсутствие двойного рисования, бюджет, сохранение массы, курсор и ограничение нового роста. Тест CLI проверяет повторяемое обнаружение без запуска; сценарий работающего headless-процесса подтверждает сохранение ручной паузы.

Настоящие hotplug, смена порта, смешанный DPI, меню «Пуск» и уведомления, графический результат на Windows 10/11 и нагрузка остаются Not run. Результаты: [TEST_RESULTS_GEOMETRY](../TEST_RESULTS_GEOMETRY.md).
