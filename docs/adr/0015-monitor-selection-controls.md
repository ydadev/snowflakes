# ADR 0015 Выбор мониторов в настройках и CLI

Статус: принято для P2-01/03. Дата: 13 ноября 2026 года.

## Решение

Панель предлагает все экраны, основной экран или выбранные. Список подключённых экранов показывает разрешение и основной экран; порядок строк определяется их положением на виртуальном рабочем столе. Номер строки не является номером из настроек Windows и не сохраняется как идентификатор. Для выбора используется ID из [ADR 0014](0014-display-identities-and-accumulation-masks.md).

Список реализован стандартным Win32 LISTBOX с LBS_MULTIPLESEL и LBS_NOTIFY. Щелчок переключает выделение; клавиатура использует поведение системного контрола. Программная установка выделения не генерирует LBN_SELCHANGE. Источники: [List Box Styles](https://learn.microsoft.com/en-us/windows/win32/controls/list-box-styles), [LBN_SELCHANGE](https://learn.microsoft.com/en-us/windows/win32/controls/lbn-selchange).

Выбор экранов редактируется как черновик и применяется кнопкой «Применить экраны». Режим и список ID передаются одной Setting::Display, проверяются общим валидатором и сохраняются до изменения Session. Для selected требуется 1–16 различных ID; для all/primary список пуст. Неверное значение или отказ записи оставляют прежний профиль целиком. Изменение не снимает ручную паузу.

CLI использует тот же путь: --monitors all, --monitors primary, --monitors selected ID [...]. Неизвестный сейчас ID допустим: монитор может быть отключён. Автоматического перехода на все экраны при отсутствии выбранных нет. В серверном режиме редактирование отклоняется; снятие галочки возвращает независимый местный выбор. Формат профиля v2 не меняется, поле display уже входит в контракт.

## Обнаружение и обновление

Владелец состояния обновляет список мониторов раз в две секунды вне GUI-потока. Отдельный DPI-контекст обеспечивает физические координаты. Внутренний View содержит ID, геометрию и признаки primary/persistent; пути устройств и имена драйверов не передаются. В headless-тестах периодическое обнаружение не запускается. Ошибка обнаружения обозначается отсутствием снимка, а не пустым пользовательским выбором.

Сохранённые и редактируемые ID отсутствующих мониторов остаются строками списка. Обновление сопоставляет выделение и позицию списка по ID. До 32 подключённых устройств и 32 запомненных ID ограничивают размер представления. Общий контракт по-прежнему разрешает выбрать не более 16.

Подтверждение команды не затирает более поздний черновик. Закрытие панели отбрасывает неприменённый черновик; уже отправленная команда продолжает выполняться. Переключение в серверный режим показывает его профиль и отключает редактирование. Очередь объединяет повторные полные команды выбора внутри интервала источника.

Изменение display запрашивает обновление геометрии графического потока, не ожидая очередной секундной сверки. Это не снимает системные или ручную паузы. Требуемые 200 мс применения должны быть измерены на активном рендерере отдельно.

## Проверка и границы

Проверены сохранение и повторное открытие, независимость профилей и паузы, отказ записи, неверные комбинации, очередь команд, отключённые ID и скрытые настоящие Win32-контролы. Живой изолированный headless-процесс принимает CLI-команду и сохраняет ручную паузу.

Not run: визуальная и клавиатурная приёмка панели на Windows 10/11, физическое подключение мониторов и измерение задержки применения. Периодический снимок UI не заменяет матрицу DPI/hotplug графического слоя. Результаты: [TEST_RESULTS_MONITOR_SELECTION](../TEST_RESULTS_MONITOR_SELECTION.md).
