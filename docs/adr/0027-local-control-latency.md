# ADR 0027 Измерение задержки местных настроек

Статус: принято для основы P2/P3. Дата: 13 ноября 2026 года. Основание: CT-10 и необходимость отделить задержку управления от физического перехода сугробов.

## Доставка изменений

GUI обрабатывает сообщения перед проверкой и отправкой очереди команд. Раньше сообщения обрабатывались после отправки, затем цикл безусловно ожидал до 100 мс: последняя правка могла оставаться в очереди до следующего таймера. После ответа поток управления посылает WM_NULL собственному окну GUI и потоку графики. Очередь сообщений графического потока создаётся до публикации его ID; при завершении ID сбрасывается. Ожидание сообщений и прежние таймеры сохраняются, активного опроса нет.

Настройки по-прежнему сохраняются потоком управления до применения. Объединение одинаковых правок не пересекает переключение источника, адреса и пресета. Исправление доставки не меняет физический шаг, распределение размеров, накопление или ручную паузу.

## Локальная трасса

Новый необязательный флаг запуска --trace-latency принимает абсолютный путь нового файла. Существующий файл не перезаписывается. Подключать трассу к работающему экземпляру или к отдельной команде нельзя. По умолчанию запись выключена. Флаг не входит в профиль, статус или сетевой контракт.

Для правок Command::Set из панели создаётся внутренний Trace. Он проходит через ограниченную очередь GUI, Envelope управления и внутренний View, не сериализуясь в IPC или status. Записываются числовой ключ типа команды, ID и монотонное время от создания Trace:

| Стадия | Наблюдение |
| --- | --- |
| input | Обработчик панели ставит разобранную правку в очередь; физический ввод и доставка сообщения до обработчика не измеряются |
| dispatch | GUI передаёт правку потоку управления |
| received | Поток управления получил правку |
| applied | Controller успешно вернул результат после сохранения и применения |
| observed | Графический поток прочитал View с этой правкой |
| submitted | Новый цикл отрисовки завершился без ошибки и хотя бы один выбранный неприостановленный слой успешно вернул Present |

Submitted не означает окончание работы GPU, показ DWM, появление пикселя или задержку на всех дисплеях. Пауза, ограничение FPS, отсутствие слоёв и ошибка графики не создают такую отметку. Повторное чтение и повторные кадры не дублируют стадии. superseded означает, что следующая правка заменила запись до регистрации подтверждения кадра; это не доказывает, что старый снимок никогда не рисовался. rejected отмечает отказ, evicted — вытеснение незавершённого измерения.

Пределы: 128 незавершённых измерений, асинхронный канал 256 событий и файл до 2 MiB без ротации. try_send не ждёт диска. Заголовок содержит версию схемы/продукта и display_latency_measured=false, заключительная запись — dropped, write_errors и unfinished. Завершение процесса закрывает канал и дописывает очередь. Аварийное завершение может оставить файл без заключительной записи. Потери, ошибки, вытеснение и незавершённые записи нельзя трактовать как успешные измерения.

Значения настроек, адрес сервера, имена компьютеров/окон, пути и реквизиты в события не попадают. Рабочие трассы остаются вне Git. Запись сама создаёт дополнительную нагрузку; сравнение с выключенной диагностикой остаётся частью будущих измерений.

## Подтверждение и границы

Скрытые Win32-контролы проверяют происхождение токена, объединение правок и отказ переполнения. Настоящий поток управления проверяется на временном профиле с реальной атомарной записью и двумя скрытыми очередями сообщений. Рендерер при этом не запускается. Набор и предварительное измерение описаны в [результатах](../TEST_RESULTS_CONTROL_LATENCY.md).

Полный путь ввод → сохранение → видимый кадр, Windows 10, многомониторная нагрузка, CPU/GPU/память и длительная работа остаются открытыми. CT-10 не засчитан. Рабочий эффект автоматически не возобновляется.
