# ADR 0028 Внешний сбор ресурсов клиента

Статус: принято для проверки основы P2/P3; полная приёмка производительности открыта. Дата: 13 ноября 2026 года.

## Сбор без изменения эффекта

tools/measure-resources.ps1 работает в отдельном Windows x64 PowerShell 5.1+ процессе. Он вызывает только --status --json и --list-monitors --json, проверяет PID/сеанс и следит за исходным экземпляром процесса. Отсутствие клиента, несовпадение сеанса, завершение/замена процесса и ошибка запроса не запускают приложение. Сборщик не меняет профиль, интенсивность или причины паузы.

CPU и private bytes/working set читаются через System.Diagnostics.Process. CPU вычисляется по разности TotalProcessorTime и фактического монотонного времени, нормированной на число активных логических процессоров всех групп. Для количества используется [GetActiveProcessorCount](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getactiveprocessorcount). Среднее взвешено длительностями интервалов, а не числом отсчётов.

GPU читается локальным PDH через [PdhAddEnglishCounterW](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhaddenglishcounterw) и [PdhGetFormattedCounterArrayW](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcounterarrayw). Языконезависимые пути ограничены PID клиента и одного DWM того же сеанса. Отдельно записываются максимум загрузки среди 3D engine процесса, сумма Total Committed по его адаптерам и максимум 3D engine DWM. Проценты независимых engines не складываются. GPU требует соответствующего драйвера и доступных счётчиков; [Microsoft описывает требования и выбор самого занятого engine](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/).

Недоступность, пустой массив, плохой статус экземпляра, отрицательное/нечисловое значение или выход процента за 0–100 дают unavailable и null. Только действительный нулевой отсчёт даёт 0. Native-буфер ограничен 1 MiB, число экземпляров одного счётчика — 64, попытки чтения при смене массива — три. Имена экземпляров, пути и имена компьютеров не записываются.

DWM повторно проверяется по PID и сеансу; после смены PID его данные становятся недоступны до нового сбора. Время процесса защищённого DWM не требуется. Числа DWM включают работу остальных приложений: добавочная нагрузка определяется парным фоновым замером, а не объявляется по абсолютному значению. Для GPU Process Memory известны [ошибочные показания Windows](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/gpu-process-memory-counters-report-wrong-value); они записываются как данные провайдера, требующие независимой сверки перед приёмкой.

## Формат и ограничения

В новом NDJSON-файле хранятся header, sample, state при обнаруженном изменении и summary. Существующий файл не перезаписывается. Предел — 64 MiB с резервом для summary, продолжительность — до восьми часов, интервал — 1–10 секунд. Последний дробный интервал тоже использует sleep; целочисленная перегрузка Math.Min не допускается. Прогрев исключён из расчёта CPU и первого интервала PDH. Измеряемое CPU-окно отсчитывается от исходного снимка процесса.

Заголовок включает версию и SHA256 целевого/запросного EXE без путей, режим и параметры, ОС, CPU/RAM, описания GPU/драйверов и геометрию мониторов. Местный профиль проецируется по явному списку погодных полей; дополнительные поля отбрасываются. Адреса, hostname, SID, реквизиты, пути профилей, содержимое и заголовки окон отсутствуют. Сырые файлы с конфигурацией стенда остаются вне Git. Состояние проверяется примерно раз в пять секунд; краткие изменения между проверками могут быть пропущены, снимки не являются непрерывной трассой.

Итог содержит покрытие каждого GPU-счётчика, среднее по доступным интервалам, максимум памяти и изменение private bytes после прогрева. Частичный прогон и отсутствие метрики не дают успешную приёмку; acceptance всегда not_evaluated. Нагрузка сборщика, чтение статуса и конкурирующая работа учитываются при планировании сравнения.

В исходной версии FPS и p95 были явно null/not_available: реализован сбор ресурсов, без подмены частоты значением target_fps. Продолжение [ADR 0029](0029-per-display-present-metrics.md) добавляет отдельные счётчики Present; показанный DWM кадр и CT-10 остаются открытыми. [Проверки](../TEST_RESULTS_RESOURCE_COLLECTION.md) не завершают P2/P3/P7.
