# ADR 0039 Замер снеговой модели без графики

Статус: принято для P3-04 и подготовки ресурсной приёмки. Дата: 14 ноября 2026 года.

## Задача

Нужен воспроизводимый замер модели при обычном снегопаде и заполненном материальном пуле. Включение рабочего эффекта сейчас не разрешено. Существующий сборщик ресурсов обращается к действующему клиенту, поэтому новый эксперимент выполняется отдельной консольной программой без профиля, IPC, окон и графических устройств.

## Исполнение

Cargo example snow_model_bench использует настоящий World и фиксированный seed. Запускается только release-сборка. CLI ограничивает измерение 60–36000 шагами, прогрев 0–3600 шагами; между итерациями проверяется лимит 300 секунд измеряемого цикла. Симуляция идёт без ожидания реального времени. Отчёт — одна строка JSON со своей schema_version=1, без имён компьютеров, путей и реквизитов.

Сценарий baseline содержит один синтетический экран 1920×1080 при 100%, десять окон, 50% интенсивности и 35% накопления. Начальный слой — 1 DIP на крышах и 2 DIP внизу, затем выполняются настоящая эмиссия, движение и таяние.

Сценарий material-stress содержит два экрана 3840×2160 при 200%. Закрытые исходные крыши дают связные тела; их копии заполняют активный допуск 4800. Ещё 252 накопленных крыши закрываются через set_scene и создают очередь материала. Эмиссия и таяние выключены, предел накопления 100%. После каждых 120 шагов сцена повторяется с прежним seed, поддерживая насыщение. Старый World уничтожается до создания нового. Это повторение синтетических эпизодов, не естественный длительный сеанс приложения.

## Метрики и проверки

Время каждого World::step измеряется отдельно от подготовки, переинициализации и наблюдения. Хранятся не более 36000 длительностей; p50/p95/p99 вычисляются точным методом ближайшего ранга. Число шагов дольше DT относится к модели, не к пропускам показанных кадров.

World::budget_snapshot по явному запросу возвращает число активных пластов, ячеек, пакетов, ожидающих тел и масок. Обычный шаг не вызывает этот метод. В эксперименте снимок и баланс проверяются через каждые 30 шагов и на границах эпизодов; максимумы и минимум активного пула являются наблюдёнными значениями. В JSON раздельно представлены пакеты и их части.

На Windows GetProcessTimes читает CPU только текущего процесса, а GetProcessMemoryInfo — его private bytes и working set. Пики относятся к жизни процесса до последнего снимка, включая прогрев и подготовку. CPU измеряемого интервала включает переинициализации и наблюдение; нормировка использует указанное число доступных логических процессоров. При ошибке API замер завершается с причиной; на других ОС нативные поля отсутствуют с явным unsupported_platform.

Windows FFI находится только в примере и использует текущий псевдодескриптор. Нового фонового опроса в клиенте нет. Контракт погоды, хранилище, IPC, настройки пользователя и рендерер не меняются.

## Границы доказательства

[Методика и первые результаты](../MODEL_BENCHMARK.md) не засчитывают CPU/FPS/GPU/память готового клиента, CT-10, Windows 10 или восемь часов работы. Для них сохраняется собственная приёмка. Короткий baseline smoke входит в check.ps1 и CI для проверки работоспособности инструмента, без аппаратного порога производительности.
