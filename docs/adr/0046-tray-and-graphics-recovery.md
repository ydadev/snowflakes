# ADR 0046 Восстановление трея и причина ошибки графики

Статус: принято для P2-01/04, OS-09/10. Дата: 14 ноября 2026 года.

## Доставка значка

Прежняя обработка TaskbarCreated снимала запрос восстановления перед NIM_ADD и игнорировала ошибку. Повтор не планировался. Теперь отдельный Icon хранит этап Missing → Version → Ready и последнее успешно доставленное состояние подсказки. Первый запуск использует тот же путь: временная недоступность Shell не завершает клиент.

При отказе повтор выполняется через 1, 2, 4, 8, 16 и далее 30 секунд. Дедлайн проверяется в обычном цикле GUI; отдельный поток и очередь уведомлений не нужны. За один проход возможны не более трёх вызовов. Неизменённая доставленная подсказка не вызывает Shell API. При очередной попытке берётся актуальный статус.

Успешный NIM_ADD и неудачный NIM_SETVERSION сохраняются раздельно: повторяется выбор версии, а не добавление уже существующего значка. Успех каждого шага сбрасывает его задержку. Новый TaskbarCreated сбрасывает состояние доставки; последующие обычные сообщения не теряют запрос. Регистрационный ID 0 не трактуется как системное событие.

Windows требует NIM_SETVERSION после каждого добавления; эта операция имеет собственный результат. См. [Shell_NotifyIconW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shell_notifyiconw). Пока версия 4 не подтверждена, обработчик поддерживает прежние сообщения выбора/меню. После подтверждения использует события версии 4 и младшее слово lParam. Применяется NIF_SHOWTIP: стандартная подсказка иначе подавляется в версии 4. Автоматические сообщения состояния не используют NIF_INFO. См. [NOTIFYICONDATAW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw).

## Состояние графики

Recovery выделяет существующие ограничения графики: максимум три ошибки за период включения, ожидание 2/4 секунд перед оставшимися попытками, остановка после третьей. Успешный кадр не обнуляет бюджет ошибок. Сброс сохраняет прежнее условие — переход эффекта из включённого состояния в выключенное. Ручная пауза, возвращение из сна и перезапуск Explorer не сбрасывают бюджет.

Последний неустранённый HRESULT хранится отдельно от времени кадра. Пустой список слоёв, пропуск кадра, пауза и положительный DXGI_STATUS_OCCLUDED не считаются восстановлением. Только новый принятый S_OK Present убирает причину. Это устраняет ложный нормальный статус между попытками. Физическая модель, материал и часы паузы сохраняют прежние правила.

Report передаёт числовой код в необязательное поле status.graphics_error. При отсутствии ошибки поле не сериализуется; при чтении прежнего JSON по умолчанию равно null. Это локальный статус IPC, не погодный Settings и не сетевой контракт. Нативный текст ошибки, пути и параметры окружения не передаются. Ошибка начального создания графического worker также сохраняет HRESULT.

Подсказка показывает восстановление или остановку после повторной ошибки и код в шестнадцатеричном виде. Далее по приоритету идут недоступность событий сеанса, ручная/автоматическая пауза, ожидание профиля, выключенный или работающий эффект. Обновление значка не меняет настройки, источник профиля, clear_epoch и причины паузы.

## Область проверки

Проверяются автоматы с подставленным результатом Shell, подготовка настоящей структуры NOTIFYICONDATAW и сообщения отдельному скрытому HWND. Физический снег проверяется при синтетической ошибке и ручной паузе без GPU-слоёв. [Результаты](../TEST_RESULTS_TRAY_RECOVERY.md).

Проверки не перезапускают Explorer или устройство пользователя, не создают видимый трей и не включают рабочий эффект. Нижние поверхности по-прежнему получают снимок рабочей области при периодической сверке сцены. TaskbarCreated также рассылается при смене DPI основного экрана Windows 10: [The Taskbar](https://learn.microsoft.com/en-us/windows/win32/shell/taskbar). Этот переход, нативный перезапуск панели задач и обе ОС остаются непроверенными. Эти результаты не закрывают OS-09/10 целиком.
