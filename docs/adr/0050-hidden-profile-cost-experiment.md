# ADR 0050 Изолированное измерение стоимости графических профилей

Статус: принято для диагностики EN-09/P3-04. Дата: 14 ноября 2026 года. Дополняет [ADR 0049](0049-bounded-snow-profile-cache.md).

## Задача и границы

Сокращение числа ID2D1PathGeometry не доказывает ускорение. Нужен воспроизводимый опыт с прежним рендером, кешем только путей и кешем с native realizations, включая постоянно меняющиеся формы. Рабочий эффект остаётся приостановленным; измеритель не управляет клиентом и не захватывает чужое содержимое.

Инструмент размещается в test-only модуле profile_bench. Он явно запускается как ignored release-тест, использует собственный скрытый слой 1280 × 720 и производственный Gpu::render_snow без Present. Три обычных теста проверяют достоверность расчётов и синтетическую нагрузку. В production EXE ни измеритель, ни переключение сравниваемых вариантов не входят.

## Метод

Один Gpu/target/factory обслуживает все варианты последовательно. Эталон использует прежние экранные пути, с заранее полученной factory вне измеряемого интервала. Кеши каждого блока создаются заново. До замера проверяются пиксели обоих вариантов кеша; чтение bitmap и проверка краёв не выполняются между сравниваемыми блоками.

Каждая нагрузка проходит в порядке reference → paths → realizations → realizations → paths → reference. Блок содержит 16 прогревочных и 80 измеряемых кадров. Позы меняются во всех сценах; формы либо неизменны, либо получают новое значение на каждом кадре. Отпечатки финальной формы/поз должны совпадать между вариантами, попадания и построения соответствовать фактической нагрузке. Модельная физика, IPC, трекер окон, DWM и Present не измеряются.

Измеряются отдельно:

- Wall-время вызова рендерера до возврата EndDraw. Оно включает driver/Direct2D и возможные внутренние ожидания, не является чистым временем CPU-инструкций.
- Wall-время до готовности query после отправки команд. Оно включает ожидание и издержки опроса, не является экранной задержкой кадра.
- Разность GPU timestamp в проверенном disjoint-интервале. Это прошедшее время между командами в GPU timeline; возможны промежутки подачи команд CPU, поэтому поле называется gpu_timeline_not_busy и не выдаётся за GPU busy time.
- Суммарное kernel+user время текущего потока за блок, включая обновление фикстуры/опрос. Из-за наблюдаемой дискретности используется как вспомогательная величина.

EndDraw отправляет накопленные команды; сам возврат не подтверждает завершение GPU. Flush также асинхронен. [EndDraw](https://learn.microsoft.com/en-us/windows/win32/api/d2d1/nf-d2d1-id2d1rendertarget-enddraw), [D3D11 Flush](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-flush).

Одна пара timestamp охватывается TIMESTAMP_DISJOINT. Данные с Disjoint=true, нулевой частотой или обратным порядком отбрасываются и явно считаются. PIPELINE_STATISTICS должен показать ненулевые вызовы pixel shader в каждом кадре. Это проверка наличия рисования внутри query, а не точного процента занятости GPU. [Типы query](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ne-d3d11-d3d11_query), [disjoint](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/ns-d3d11-d3d11_query_data_timestamp_disjoint).

GetData вызывается на immediate context с сохранением исходного HRESULT: только S_OK означает готовность, S_FALSE — ожидание. Binding Result<()> стирает это различие, поэтому ограниченный unsafe-вызов vtable находится только внутри тестового измерителя. Native тип результата должен точно совпадать с query. На опрос одной группы отведено до двух секунд; цикл эксперимента ограничен 60 секундами и не повторяет сбойный опыт автоматически. [GetData](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-getdata).

Принудительные Flush и ожидания служат сериализации опыта. Они не добавляются в рабочую отрисовку. Тест выводит нейтральные JSON-записи с единицами, размером нагрузки, счётчиками, mean/nearest-rank p50/p95/max и числом недостоверных GPU-образцов. Тесты не требуют, чтобы один вариант оказался быстрее: это измерение, а не нестабильный тест скорости.

## Результат

[Первый сопоставимый прогон](../TEST_RESULTS_PROFILE_COST.md) подтвердил различие CPU wall и GPU-интервала. Native realizations не объявляются универсальным ускорением. Выбор политики их применения требует дальнейшей изоляции стоимости AA/заливки/обводки и разрешённой видимой ресурсной приёмки на Windows 10/11. Производственная политика этим измерительным изменением не меняется.
