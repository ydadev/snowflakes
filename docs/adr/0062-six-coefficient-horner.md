# ADR 0062 Horner для шести коэффициентов

Статус: принято для части EN-09, P3-02/04. Дата: 14 ноября 2026 года. Развивает [runtime-вычислитель](0058-runtime-fused-contact-evaluation.md) и [уточнение ошибки](0061-contact-roundoff-enclosure.md).

## Основание

В отдельной диагностической копии около 90% уточнений contact-global используют полином пятой степени. После уменьшения числа итераций стоимость одной последовательности fused вычислений остаётся существенной. [Измерения и проверки](../TEST_RESULTS_SIX_COEFFICIENTS.md).

## Решение

Внутренний horner проверяет длину среза. При шести коэффициентах он выполняет шесть последовательных mul_add от старшего коэффициента к младшему без цикла. Остальные длины используют прежний цикл; переносимый value остаётся независимым fold для сравнения. Путь применим также внутри границы/уточнения, где вызывается тот же horner.

Сохраняются начальное значение 0.0 и первая операция 0.0.mul_add(x,a₅). Начинать непосредственно с a₅ нельзя: например, при бесконечном x исходное умножение нуля определяет NaN. Сохраняются порядок всех операций и fused округление; замена последней операции на умножение/сложение теряет малый результат при компенсации. Гарантия одного округления описана в [Rust mul_add](https://doc.rust-lang.org/stable/std/primitive.f64.html#method.mul_add).

CPU/OS-проверка, наблюдаемый backend, сигнатуры, unsafe-граница и fallback не меняются. Не меняются производная, E=16εZ, бюджет 56−d, остановка по нулю/соседним float, силы, маски, первый удар или масса. Здесь нет нового приближения полинома.

## Подтверждение и ограничения

Два новых сценария сравнивают конечные биты, signed zero и классификацию NaN/Infinity с прежним fold. Мутации удаления начальной операции и раздельного последнего округления получили Failed, исходник восстановлен побайтно. Прежние сравнения по разным степеням, корням и состояниям World сохраняются. NaN payload не является заявленной гарантией.

Приёмка производительности требует отдельного A/B/B/A окончательных сборок. Выигрыш в одной нагрузке не закрывает общий бюджет, непрерывный поток, ресурсы полного клиента или нативные проверки обеих ОС. Рабочий эффект не запускается; вода, сайт и поставка отложены.
