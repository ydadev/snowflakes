# ADR 0076 Уведомления локальной политики

Статус: принято для основы P2. Дата: 15 ноября 2026 года. Продолжает [Windows runtime](0006-windows-runtime-ipc.md). [Проверки](../TEST_RESULTS_POLICY_NOTIFICATIONS.md).

## Основание

ТЗ требует перечитывать локальные ограничения по уведомлению реестра с резервом 60 секунд. До изменения runtime использовал только периодическое чтение. Удаление политики должно возвращать сохранённые пользовательские значения; применение ограничения не должно перезаписывать профиль или снимать ручную паузу.

## Решение

Чтение прежних DWORD и их проекция в Limits выделены в platform/policy. Производственный Source фиксирован на HKLM\\Software\\Policies\\Snowflakes, 64-битное представление. RegOpenKeyExW для уведомлений запрашивает только KEY_NOTIFY; чтение сохраняет прежнюю проверку типов. Клиент не создаёт ключей и не меняет их ACL. Ошибка чтения закрывает сеанс по политике, как раньше; ошибка регистрации уведомлений оставляет резервный опрос.

Существующий поток управления владеет Monitor, без дополнительного потока или сервиса. На Software и Policies регистрируются изменения непосредственных имён/безопасности, на Snowflakes — значений/безопасности. Это замечает удаление и повторное создание промежуточного ключа, включая изначально отсутствующий, без рекурсивного наблюдения всех значений Software.

Все однократные асинхронные регистрации используют одно событие. После сигнала создаётся новый набор с другим событием, затем закрывается старый. Ключи старого набора закрываются до его события; их закрытие не может сигнализировать новое. Повторная регистрация незавершённого ожидания на том же handle исключена. В рабочем состоянии — до трёх ключей и одного события; при замене одновременно существуют до двух наборов. REG_NOTIFY_THREAD_AGNOSTIC исключает зависимость регистрации от завершения вызывающего потока.

Новый набор вооружается до чтения значений. Первое такое чтение выполняется перед обработкой первой команды, закрывая интервал между первоначальной проверкой запуска и работником. Изменения объединяются: повторное чтение не чаще одного раза в 100 мс; событие остаётся установленным до обработки. Проверка события неблокирующая, используется прежний цикл с ожиданием команды до 100 мс. Это расписание, а не гарантия реального времени под нагрузкой. Резервное чтение и восстановление наблюдения выполняются через 60 секунд после предыдущего чтения, в том числе без работающего watch.

Limits применяются единственным владельцем Session, снимок публикуется и будит GUI и графический поток. Ожидающая команда не применяется после закрытия политикой. Изменение Enabled не запускает новый процесс; StartAtLogon остаётся проверкой отдельного запуска при входе. Погодная физика, схема IPC и местный формат сохраняются.

## Границы

Значения реестра не образуют атомарную транзакцию GPO: параллельная правка может потребовать следующего чтения. RegRestoreKey не даёт таких уведомлений, поэтому резерв сохраняется. Реальная доставка доменной GPO и приёмка HKLM на Windows 10/11 остаются отдельными проверками. Тестовый Source с временным HKCU существует только при cfg(test), без CLI и переменных окружения. Вода, регистрация, HTTP, сайт и развёртывание отложены.
