# ADR 0081 Проверка Worker на заданном startup desktop

Статус: принято для испытательного стенда P1-03/04 и P2-04. Дата: 15 ноября 2026 года. [Результаты и ограничения](../TEST_RESULTS_PRIVATE_WORKER.md).

## Основание

SetThreadDesktop у тестового родителя не задаёт desktop для всех будущих потоков процесса. Worker создаёт новый поток, затем собственные очередь, hooks, Observer и графические окна. Для безопасной проверки этого пути нужен отдельный процесс с явно указанным startup desktop, а не предположение о наследовании desktop вызывающего теста.

## Решение

Явно запускаемый hardware probe создаёт desktop с уникальным синтетическим именем и передаёт его в STARTUPINFOW.lpDesktop при CreateProcessW того же библиотечного тестового EXE. Родитель не присоединяется к нему, не наследует handles, не вызывает SwitchDesktop и использует CREATE_NO_WINDOW/STARTF_FORCEOFFFEEDBACK. Его handle не запрашивает DESKTOP_SWITCHDESKTOP. Имя и UOI_IO=false проверяются до запуска и после завершения ребёнка.

Только в cfg(test) Worker проверяет startup desktop и desktop собственного потока до создания очереди, hooks и окон. Дочерний сценарий работает с временным UserStore и отдельными View/Report/Conditions. Он не запускает трей, IPC, сетевой опрос или рабочий экземпляр. Данные передаются частным Unicode environment block без изменения окружения родителя. Ребёнок ограничен 30 секундами; при отказе guard завершает принадлежащий ему process handle.

При добавлении вложенного NativeTestHost launcher получил собственный анонимный Job Object с JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE. Ребёнок создаётся CREATE_SUSPENDED, назначается в job до ResumeThread; его принадлежность проверяется. Handle не наследуется, breakaway не разрешается. Закрытие последнего handle завершает оставшихся членов собственного дерева; чужие PID не разыскиваются. После нормального выхода accounting ожидается до 2 секунд до нуля активных процессов. Job API — Windows dev-dependency. [Основание Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

Настоящий Observer и причины системной паузы не подменяются. Если состояние сеанса разрешает работу, проверяются Present-счётчики каждого слоя, частицы, ручная пауза, неподвижность счётчиков/частиц, очистка, возобновление с прежними HWND и уничтожение слоёв. Если сеанс запрещает работу, проверяются готовность Observer, отсутствие слоёв/частиц/Present и удержание запрета; полный активный цикл отмечается Not run. Успешное завершение диагностической пробы не означает Passed для всех её фаз.

После остановки Worker отдельно испытывается нижний графический слой на том же невходном desktop: настоящий Layer/Gpu, PMv2, DPI от HWND, буфер 256×256, синтетическая снежинка после появления, чтение alpha и четыре вызова Layer::draw. Это отдельная проверка рендера, а не обход состояния Worker. Исходные HRESULT Present записываются через test-only thread-local наблюдатель; счётчик увеличивается только для S_OK. Положительный статус DXGI не объявляется успешной отправкой. Ошибка после создания ресурсов проваливает пробу; недоступность начального создания фиксируется отдельно как Not run.

## Продолжение: выбор дисплея

[Нативный сценарий Weather/Layer](../TEST_RESULTS_NATIVE_LAYER_SELECTION.md) использует тот же launcher с отдельной exact-точкой входа и типом отчёта. PMv2 scope общий, имя/UOI_IO и владение процессом проверяются прежними guards. Дополнительная трасса Present включается только явно на тестовом потоке, ограничена 64 кодами и выключена в обычных вызовах.

Сценарий сверяет настоящие рамки мониторов с HWND, bitmap, swap chain и World.scene; переключает All/Primary/Selected/недоступный выбор/All и проверяет удержание/освобождение ресурсов. Настоящая очередь обрабатывается, готовность сцены ожидается с пределом 3 секунды без подмены Source; в ожидании не должно быть Present. Отдельный доступный второй монитор обязателен для соответствующей ветви, иначе она Not run. Это проверка нижнего update-пути, а не отмена системного запрета полного Worker.

## Продолжение: снег окна в GPU-буфере

[Связанный Native/Weather/World/Gpu](../TEST_RESULTS_NATIVE_SNOW_PIXELS.md) использует прежний Host через узкий cfg(test) re-export. Префикс startup desktop уточнён до SnowflakesNative-GpuProbe-, поэтому сохраняются оба строгих семейства проверок имени, UOI_IO, владельца и DPI. Реальная команда native-slide меняет только принадлежащее ребёнку окно с SWP_NOACTIVATE.

Для нужных кадров test-only флаг читает bitmap после EndDraw, до Present; обычные вызовы не копируют пиксели. Данные берутся из настоящего render_snow, без дополнительной перерисовки. Пиксели старой/новой крыши, падающего материала и пола сопоставляются с массой World. Шаги времени явные; ускоренный прогон не принимается за wall-производительность или активный Worker. Масса не отбрасывается для завершения, мелкие частицы ожидаются при тех же силах с отдельным пределом шагов.

## Продолжение: нативные маски

[Перекрытие/cloak в GPU](../TEST_RESULTS_NATIVE_COVERAGE_PIXELS.md) расширяет связанный стенд с прежними guards/Job Object. Частичное переднее окно перемещается только дочерней командой SetWindowPos/SWP_NOACTIVATE; Root проверяет настоящие DWM-рамки и порядок Native. Снимки до Present сопоставляются с массой, сохранённым ключом и прохождением новых частиц. Отдельный сценарий скрытого закрытия требует прозрачного всего bitmap, нулевого пола и учтённого removed_mass.

Начало Registry берётся read-only test getter из Tracker, поэтому условие до секундной сверки не опирается на более позднюю отметку запуска сценария. Начальные скорость/возраст контрольной частицы заданы тестом; её дальнейшие позы вычисляет World. Число тел, близость X и removed_mass исключают подмену прохождения другой частицей либо удалением материала. Это нижний связанный путь, а не изменение Observer-гейта или подтверждение видимого вывода.

## Продолжение: естественное заполнение

[Обычный снегопад в Native/GPU](../TEST_RESULTS_NATIVE_NATURAL_SNOW.md) использует тот же launcher и настоящие NativeTestHost/Weather/World/Gpu. Сцена начинается с нулевой массы; материал вводит только производственный emitter после изменения интенсивности. Начальные профили, ledger и частицы тестом не задаются. Сверяются отдельные моменты рождения и оседания, распределение радиусов и накопление настоящей крыши.

При переходе к интенсивности 0 введённая масса фиксируется после последнего кадра с осадками и должна оставаться точно неизменной на каждом следующем шаге. Уже летящий материал ожидается при прежних силах с пределом 7200 STEP. Финальный снимок принимается только при пустых телах/очереди; баланс включает все опоры и учтённый выход. Guards/Job Object, Watchdog и ограничения видимого вывода сохранены. Это проверка обычного пути создания снега, а не новый режим физики или обход системной паузы Worker.

## Продолжение: resize естественного запаса

[Расширение и оба среза в GPU](../TEST_RESULTS_NATIVE_RESIZE_PIXELS.md) получают весь запас обычным emitter, прекращают приток и ждут исчезновения летящих тел. Прежние команды NativeTestHost меняют настоящую ширину/край; независимый f64-интеграл физических интервалов сравнивается с каждой новой ячейкой mass+pending. Пиксели новой/удалённой полосы отделены от контрольного переднего окна.

Для наблюдения результата set_scene до физического шага время update увеличивается ровно на штатный DISCONTINUITY=250 мс: производственный StepClock отбрасывает этот интервал. Clock, World, очередь и паузы тестом не изменяются. На следующем STEP срез выпускается настоящей моделью, затем естественно оседает; проверяются связная масса, прирост высоты/массы пола, изменения alpha и отсутствие старого следа. Заполнение длится дольше секунды, поэтому периодическая сверка разрешена и результат не приписывается только WinEvent. Это не доказательство непрерывного перетаскивания или wall-задержки. Отдельный ребёнок на каждый край сохраняет прежние guards и Job Object.

## Продолжение: процентные настройки

[Естественные частицы в Weather/GPU](../TEST_RESULTS_NATIVE_APPEARANCE_PIXELS.md) сравниваются при одном timestamp после штатного DISCONTINUITY. Модель не шагает между настройками; радиусы/массы проверяются относительно сохранённых копий, остальные поля частиц и весь запас опор — на точное совпадение. По [ADR 0008](0008-physical-snow-and-appearance.md) размер пересчитывает массу летящих частиц и учитывает разницу в ledger, а не сохраняет прежнюю массу тела. Заметность должна сохранять полный test-only Debug-снимок World и изменять только пиксели.

Воздушная полоса исключает лежащий снег; проверяются нулевая альфа, её рост, тёмный контур выше 100% и побайтный возврат исходного кадра. Настоящее закрытие естественно наполненной крыши создаёт пласты. При нулевой заметности они остаются видимыми, а смена размера 25/200/100% сохраняет их полное состояние и весь bitmap материала. Прежние guards/Job Object и пределы аппаратного launcher сохранены. Сравнение в неподвижном времени не заменяет ввод, непрерывную анимацию или показанный кадр.

## Продолжение: частота рождений

[Интенсивность в Native/GPU](../TEST_RESULTS_NATIVE_EMISSION_PIXELS.md) считает новые обычные тела по возрасту после каждого настоящего update: один STEP при 60 Гц, два при 30 Гц. Отсеиваются пласты и материал с skip_support, проверяется положение около настоящей плоскости рождения. Сумма их массы сверяется с приростом introduced_mass каждого кадра; живой пул не используется как счётчик рождений. Источник, ledger и тела не подставляются.

Калибровка 65 рождений/с при 100% на 1920 DIP проверяется на фактической логической ширине до насыщения с допуском одной частицы. Накопление и уход старых частиц должны реально происходить. Два свежих ребёнка с прежними guards/Job Object сравнивают только число рождений при 30/60 модельных Гц; seed, физические состояния и пиксели между ними не приравниваются. При 0% требуется отсутствие рождения/притока на каждом шаге при продолжающемся изменении GPU-кадра. Это ускоренная модельная частота update, а не wall-FPS или длительная приёмка.

## Продолжение: раннее восстановление

[Minimize/restore до приземления](../TEST_RESULTS_NATIVE_RESTORE_PIXELS.md) получает крышу обычным снегопадом и ждёт конца прежнего воздуха перед сворачиванием. Настоящий HWND становится iconic и исключается Native; очередь освобождает материал. Restore вызывается после ухода всего материала ниже полосы крыши, пока тела ещё летят. Новая генерация начинает с нулевой массы, прежняя отсутствует.

Переход сцены наблюдается без физического шага через штатный DISCONTINUITY. Сравниваются все тела исходной опоры: положение/скорость, масса/радиус, угол/вращение, возраст, вид, исходная опора, профиль slab и текущая физическая единица DPI. Приватное previous_pose не сравнивается: производственный сброс интерполяции намеренно его меняет. Проверяются вся масса и связная доля, пиксели до/после restore и окончательное оседание с приростом массы/высоты/alpha пола. Прежние guards/Job Object сохраняются; длинное накопление допускает periodic reconciliation и не доказывает wall-задержку WinEvent.

## Продолжение: скрытая панель и профиль

[Мост панели/профиля/GPU](../TEST_RESULTS_NATIVE_CONTROL_BRIDGE.md) связывает настоящие Panel, очередь Owner, Controller, временный UserStore и опубликованный View с нижним Weather::update на отдельном потоке. Узкие cfg(test) методы работают только при обязательном startup-desktop guard, PMv2 и проверке владельца/скрытого состояния контролов. GPU сначала проверяет desktop, устанавливает PMv2, затем проходит полный guard до создания HWND. Runtime/panel не дублируются.

Проверяются синтетические trackbar-сообщения, объединение, реальная запись/отказ атомарной замены, WM_NULL для GUI-окна и другого GPU-потока, соответствие токена и bitmap. Изолированный отсутствующий HKCU-источник политики и временный профиль исключают рабочие настройки. Ручная пауза сохраняется, Conditions остаются неготовыми; настоящий Observer/Worker не создаются. Прямой нижний вызов не объявляется активным Worker или подтверждением CT-10. Настоящая трасса по [ADR 0027](0027-local-control-latency.md) не получает искусственных observed/submitted; последний применённый токен остаётся unfinished. Все ролевые потоки завершаются перед выходом из собственного Job Object.

## Продолжение: регулятор сугробов

[Регулятор сугробов](../TEST_RESULTS_NATIVE_DRIFT_CONTROL.md) переиспользует мост Panel/Owner/Controller/UserStore/View на естественно накопленном запасе настоящего NativeTestHost. Дополнительные шаги модели не изображают новые команды или WM_NULL. Нулевой шаг после снижения/увеличения сверяет все профили и bitmap; активный переход и новое накопление сверяются отдельно. f64-оракул ёмкости обеих опор не вызывает product capacity/remove и применим к неизменному однородному DPI этой сцены. Производственные силы и двухсекундный срок ADR 0021 сохраняются.

## Продолжение: движение естественного запаса

[Движение естественного запаса](../TEST_RESULTS_NATIVE_NATURAL_MOTION.md) использует прежние NativeTestHost/Weather/GPU и обычный emitter. Новая команда native-nudge изменяет только принадлежащее Host окно с прежними guards/NoActivate. Видимые DWM-рамки сравниваются по смещению, без приравнивания внешнему Win32 rect. Короткие фазы используют одиночные STEP и штатный интервал 30 мс после нативной команды; долгий неподвижный хвост допускает два STEP на update при прежних силах и watchdog. Это не новый режим физики или подмена системных гейтов.

## Продолжение: нулевой размер накопления

[Нулевой размер накопления](../TEST_RESULTS_NATIVE_ZERO_ACCUMULATION.md) переиспользует прежние Probe и GPU-поток без повторения Owner/Controller. Sample дополнен массой обеих опор/воздуха и текущими физическими полями тел; буферы/подробные поля не сериализуются. Настоящая заметность 0 изолирует накопление в bitmap, одновременно проверяются положительные рождения/масса воздуха. При нулевом накоплении возврат заметности 100% обязан дать пиксели летящих снежинок при том же физическом состоянии, обратная заметность 0 возвращает пустой bitmap. Нулевой шаг при смене предела не меняет физический воздух. Guards, ручная пауза, Conditions и реальные WM_NULL сохранены; прозрачный кадр не объявляется выключенным снегопадом.

## Границы

Точки входа всех аппаратных сценариев ignored и не запускаются обычным CI. Для исходной пробы поля worker_cycle/gpu_layer и исходные коды обязательны для чтения результата; probe_completed описывает завершение диагностики. У сценария выбора экрана отдельно проверяется distinct_secondary. Не делать вывод о видимом кадре, реальном вводе, FPS DWM, mixed DPI, device loss, ресурсах всего клиента или Windows 10/11 по этим пробам. Повторять их при новом сценарии или изменении стенда, а не для накопления одинаковых OCCLUDED.

Основания Windows API: [подключение потока к desktop](https://learn.microsoft.com/en-us/windows/win32/winstation/thread-connection-to-a-desktop), [STARTUPINFOW.lpDesktop](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-startupinfow), [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), [SetThreadDesktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddesktop) и [статусы DXGI](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status).
