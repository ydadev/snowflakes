# ADR 0090 Локальный журнал ошибок клиента

Статус: принято. Дата: 15 ноября 2026 года.

## Основание

Раздел диагностики TECHNICAL_SPEC требует пять локальных файлов по 2 МиБ. Прежняя опциональная трасса задержки панели ограничивала один файл и не сохраняла обычные обработанные ошибки. Это отдельный пробел основы клиента P2.

## Решение

Владеющий экземпляр запускает один фоновый Recorder в своём процессе. Каталог — logs внутри UserStore; на исправном запуске он не создаётся до первой ошибки. Текущий errors.jsonl и четыре предыдущих errors.1.jsonl–errors.4.jsonl ограничены каждый 2 097 152 байтами. Перед добавлением записи выполняется ротация, открытый текущий файл предварительно закрывается.

Несколько писателей общего хранилища согласуют добавление и ротацию через стабильный .errors.lock и [File::try_lock](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock). Блокировка ожидается только писателем, максимум 100 мс; завершение прекращает ожидание. Несотрудничающие программы этим протоколом не защищены. Каталоги и неподходящие файлы в зарезервированных слотах не удаляются; повреждённый незавершённый хвост исправляется ограниченным чтением последних 512 байт.

Производитель передаёт фиксированный вид ошибки и числовой HRESULT/OS-код либо категорию хранения через try_send. Ёмкость очереди 128, максимальная запись 512 байт. Сериализуются только версия схемы/продукта, время Unix в миллисекундах, вид и код. API не принимает произвольный текст, пути, значения профиля, заголовки окон или идентификаторы пользователя.

Подключены отказы хранения, политики, запуска IPC, трея/панели, системного наблюдения, дисплеев, курсора и графики. Graphics Recovery пишет событие непосредственно при отказе: периодический Report может потерять промежуточное состояние. Одинаковая неустранённая графическая ошибка не повторяется; успешный принятый вывод позволяет записать новый эпизод. Сброс автомата сохраняет привязку Recorder и прежние пределы восстановления.

Обычные CLI-команды существующему экземпляру не запускают писателя. Протокол Status, настройки, физика и графические примитивы сохраняются. Опциональная трасса задержки остаётся отдельным механизмом. Сервис и сетевые запросы не добавляются.

## Границы

Запись выполняется по возможности: переполнение и ошибки диска считаются внутренними счётчиками без рекурсивного журналирования. Они не добавляются в IPC. Последний владелец ждёт завершения максимум одну секунду, затем оставляет писателю штатное завершение на следующей безопасной границе. Блокирующий системный файловый вызов принудительно не прерывается. fsync и сохранность после потери питания не гарантируются.

Проверки независимых файловых handles выполняются потоками; полная многопользовательская/многосеансовая приёмка остаётся открытой. Управляемые ошибки Recovery не заменяют настоящий device loss. [Результаты и повторение](../TEST_RESULTS_ERROR_LOG.md).
