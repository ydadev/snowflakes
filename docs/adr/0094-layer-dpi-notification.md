# ADR 0094 Событие DPI собственного графического слоя

Статус: принято для реализации; настоящая смена DPI не принята. Дата: 16 ноября 2026 года.

## Основание

OS-04 требует PMv2 и обработки WM_DPICHANGED. Панель уже обрабатывает сообщение, но процедура GPU-слоя передавала его DefWindowProc. Tracker исключает свой процесс из WinEvent; GetDpiForWindow обновляет scale только при получении Scene. Поэтому одно уведомление своего слоя не запрашивало сверку до периодического снимка.

[Microsoft описывает WM_DPICHANGED](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged) как уведомление об изменении DPI окна, с новыми значениями и предлагаемой рамкой. Обработчик должен вернуть ноль. [PMv2](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows) оставляет ответственность за пересчёт приложению.

## Решение

Процедура зарегистрированного GPU-слоя вызывает scene::display_changed и возвращает ноль. Функция отмечает полное обновление в прежнем ограниченном thread-local Changes, общем с WinEvent callbacks. Уведомления одного потока объединяются без новой очереди, истории или HWND-данных. GPU, запросы Windows, World и профиль внутри callback не вызываются.

Tracker::poll использует общий poll_changes: забирает Changes, освобождает callback cell и продолжает прежний poll_source/Registry. Ранее дублировавший этот вход тестовый помощник WinEvent использует ту же процедуру. Сохраняются объединение 30 мс, периодическая секунда, повтор после ошибки 100 мс, подтверждение сцены и полное намерение обновить геометрию при отказе.

Рамки слоя определяются физическим прямоугольником монитора. Для обычного UI Microsoft рекомендует применять предложенную рамку через SetWindowPos. Наше проектное решение для полноэкранного прозрачного слоя — повторно получить настоящие границы через Native/Scene, затем сохранить или пересоздать Layer прежним способом. Предложенная UI-рамка не масштабируется поверх физических границ монитора; WPARAM не подменяет GetDpiForWindow. Это политика приложения, а не отдельная рекомендация документации Microsoft для таких слоёв.

На следующем пригодном снимке Weather использует GetDpiForWindow, обновляет screen.scale, World::set_scene и существующие преобразования DIP. Изменение площади/масштаба продолжает отмечать output_changed для защиты качества. Никакие новые разрешения readiness, сбросы физики, настройки, поля IPC или попытки Present не добавляются.

## Доказательство и границы

Три регрессии напрямую вызывают настоящий callback и общий Tracker-вход с управляемым Source. До добавления ветки WM_DPICHANGED все три Failed; после — Passed. Синтетические параметры не изменяют Windows DPI, рамки или ресурсы. Проверяются объединение 4096 уведомлений, полная геометрия до секундной сверки, стабильный ключ окна, отказ screens/сохранение 100 мс и изоляция потоков. Прежние ответы пропуска ввода тоже проверяются.

Это не доставка сообщения Windows, не HWND/GPU-стенд и не замер wall-задержки. Настоящий mixed DPI, перенос/hotplug, обе ОС, показанный кадр и полный Worker остаются отдельной приёмкой. [Результаты](../TEST_RESULTS_LAYER_DPI.md).
