# ADR 0095 Ввод и физические обновления независимо от вывода

Статус: принято для реализации; нативная приёмка ввода открыта. Дата: 16 ноября 2026 года.

## Основание

OS-05 требует GetCursorPos с частотой активной симуляции; EN-01 задаёт шаг 1/60 и максимум пять шагов за обновление. Прежний Weather просыпался по сроку вывода и читал курсор один раз перед несколькими шагами. При 30 FPS частота чтения снижалась, одно воздействие повторялось в догоняющем цикле. Статическое сравнение World без курсора этого не обнаруживало.

[GetCursorPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorpos) возвращает экранные координаты и имеет требования к desktop/доступу. Решение не отменяет системные паузы, не переключает desktop и не добавляет input hooks.

## Решение

StepClock::deadline возвращает срок следующего физического шага из последнего наблюдения и остатка; сброшенные часы не назначают работу. Weather/Worker ждут минимум этого срока и прежнего срока вывода. Прежние readiness, паузы, неготовая сцена/100 мс и ограничение ожидания сохраняются.

update_tick выполняет обычную сверку сцены и симуляцию; Draw/Present разрешены только при наступлении срока вывода. Промежуточное обновление не считается неудавшимся Present и не меняет счётчики отправленных кадров. Скрытие полноэкранно приостановленного слоя разрешено сразу; новый слой остаётся скрытым до первого Draw. Изменение сцены по-прежнему может подготовить/пересоздать GPU-ресурс и до срока следующего кадра.

Курсор читается внутри ограниченного цикла перед каждым действительно выполняемым физическим шагом. Нулевой шаг, пауза и отброшенный длинный интервал не читают ввод. Каждый настоящий вызов получает собственное Instant после чтения; экранное положение и скорость переводятся через текущий scale прежним способом. При сбросе/пропуске времени история скорости очищается. Догоняющий цикл получает новые текущие отсчёты, а не копию прежнего импульса; историю пропущенного настоящего движения восстановить невозможно.

Для Governor суммируется wall-стоимость промежуточных обновлений и текущего кадра, без ожиданий между вызовами. Признак перестройки также сохраняется до попытки вывода. Только она передаёт пригодность/стоимость в complete; отсутствие Present на физическом обновлении не сбрасывает историю нагрузки. Сброс часов, неготовая сцена и отсутствие слоёв удаляют частичный бюджет. Текущий Report сохраняет параметры текущего вывода; следующий срок использует результат complete. Это уточняет [ADR 0093](0093-adaptive-snow-presentation.md).

Нет нового потока, очереди позиций, глобального перехвата, настроек или полей IPC. Два дополнительных поля имеют постоянный размер. Старые нижние GPU-пробы явно запрашивают кадр через cfg(test)-обёртку update; она вызывает тот же update_tick с present=true, сохраняя прежнюю область этих проб. Она не отменяет readiness и не доказывает новый полный Worker.

## Доказательство и границы

Изолированная регрессия движущегося управляемого ввода Failed: 62 чтения вместо 120 за общий двухсекундный участок. Перед этим уже были подготовлены новые границы методов; независимое ожидание и чтение на каждом шаге ещё не были подключены. После исправления сравниваются полный Debug World, число чтений, различная частота вывода и отдельный контроль без воздействия.

Пять новых проверок постоянно выполняются в debug/release. Две прежние процедуры Weather дополнены проверкой удаления частичного бюджета и отсутствия физического срока при pending/паузе. Управляемые координаты/часы не являются настоящим вводом. Фактические задержки, плавность, CPU/GPU/питание, Windows 10/11 и полный Worker остаются открытыми: единственный поток может задерживаться внутри системного/GPU-вызова. Целевые 60 Гц не объявляются гарантией реального времени. [Результаты](../TEST_RESULTS_CURSOR_CADENCE.md).
