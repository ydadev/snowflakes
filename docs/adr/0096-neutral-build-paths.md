# ADR 0096 Нейтральные пути проверенной сборки

Статус: принято для реализации. Дата: 16 ноября 2026 года.

## Основание

Правила публикации запрещают частные пути в распространяемых артефактах. Статическая проверка прежнего EXE обнаружила 35 абсолютных путей к исходникам Cargo registry. Они оставались в диагностических строках, несмотря на strip=symbols. CodeView уже содержал только snowflakes.pdb; изменение PDBALTPATH не требовалось. Сам EXE/PDB оставались в исключённом из Git target.

EN-10 дополнительно проверяется по исходникам и настоящим PE-таблицам. Отсутствие нескольких имён API/тестов в строках EXE само по себе не доказывает отсутствие захвата. Нормальные Renderer/Prototype используют собственные swap-chain targets; readback и аппаратные fixtures ограничены cfg(test). Явные диагностические команды прототипа остаются доступными и не переименовываются в тестовый harness.

## Решение

[BuildPaths.psm1](../../tools/BuildPaths.psm1) формирует стабильные [rustc --remap-path-prefix](https://doc.rust-lang.org/rustc/command-line-arguments.html#--remap-path-prefix-remap-source-names-in-output) для workspace, Cargo и Rustup: /snowflakes, /cargo, /rustup. Для Windows учитываются оба разделителя; более узкие отображения следуют за общим. Абсолютные значения вычисляются только при сборке и не записываются в Git.

Аргументы передаются через [CARGO_ENCODED_RUSTFLAGS](https://doc.rust-lang.org/cargo/reference/environment-variables.html), разделитель 0x1f сохраняет пробелы. Прежнее encoded-окружение имеет приоритет над plain RUSTFLAGS; его аргументы сохраняются перед отображениями. Применяются обычные правила приоритета Cargo: это не слияние всех возможных rustflags из глобальной конфигурации. Команды восстановления окружения не меняют глобальные настройки. Trim-paths из unstable Cargo не включается; закреплённая stable-версия сохраняется.

[build-client.ps1](../../tools/build-client.ps1) собирает release и проверяет его; [check.ps1](../../tools/check.ps1) использует ту же политику для общего прогона. Windows CI устанавливает флаги до компиляции. Модули не содержат паролей, адресов окружения или готовых частных путей. Runtime, Cargo.lock, физика и CRT-linkage не меняются. Пути в диагностике тоже переименовываются, что может потребовать source mapping для отладки.

[check-client-artifact.ps1](../../tools/check-client-artifact.ps1) читает файл без запуска: проверяет основные PE/x64/GUI поля и отсутствие известных корней workspace/Cargo/Rustup/профиля в UTF-8 и UTF-16 с обоими смещениями. Совпавшие значения не печатаются. Это ограниченная проверка путей и заголовка, не универсальный поиск секретов, сертификат подлинности или проверка всех DLL. PDB отдельно не публикуется и этой проверкой не сертифицируется.

## Проверка и границы

Старый реальный EXE отклонён новой проверкой до пересборки. После обычного build-client и окончательного check проверка Passed: 35 путей заменены нейтральными, частных вхождений 0. 27 PowerShell assertions проверяют аргументы с пробелами/кавычками, приоритет, отсутствие изменения окружения и отрицательные PE/UTF-fixtures. Синтетический заголовок не объявляется настоящим EXE.

Импорт vcruntime140.dll остаётся внешней зависимостью, которую требуется учесть в будущей офлайн-поставке. Установка runtime/пакетов не выполняется. Аппаратная приёмка Windows 10/11, ресурсы и полный Worker не закрываются статическим анализом. [Результаты](../TEST_RESULTS_RELEASE_AUDIT.md).
