# Контракт конфигурации v1

Схема: [configuration-v1.schema.json](schemas/configuration-v1.schema.json). Полный профиль: [configuration.json](fixtures/configuration.json). Общие случаи: [configuration-cases.json](fixtures/configuration-cases.json).

Rust и PHP независимо проверяют одну конфигурацию. Третий валидатор Ajv проверяет саму JSON Schema по тем же случаям. Node.js нужен только разработчику и CI, в поставку PHP-сайта не входит.

## Границы

- UTF-8 JSON, не более 65 536 байт. Все поля полного профиля обязательны, неизвестные поля отклоняются.
- Версия схемы строго 1. Ревизия от 1 до 9 007 199 254 740 991; идентификатор поколения — UUID в нижнем регистре.
- Секреты, адрес подключения, источник управления и автозапуск находятся вне погодного профиля.
- Интенсивности и размеры — четыре независимых целых процента 0–100. Ветер каждого режима от −100 до 100; прозрачность 10–100; FPS — 30 или 60.
- Выбор экранов: all, primary либо selected. Только selected требует непустой список устойчивых идентификаторов; максимум 16, без повторов и управляющих символов.
- Отсутствующий монитор не заменяется другим: проверка доступности выполняется клиентом при применении.

Проверка транспорта дополнительно отклоняет повторные ключи, хвост после JSON и запись целых полей дробным JSON-токеном, включая 1.0. JSON Schema описывает числовое значение, поэтому лексическое правило проверяют Rust/PHP отдельно.

Этот этап фиксирует ответ с полным профилем. Регистрация, запрос sync и ack будут добавлены отдельными схемами до реализации клиентских маршрутов. Сейчас публичны только health и ready; закрытые клиентские маршруты не заменяются неавторизованными заглушками.

## Проверка

~~~text
cargo test -p snowflakes-protocol --locked
npm ci --ignore-scripts
npm run test:schema
php server/tests/run.php
~~~

Изменение поля требует согласованной правки схемы, обеих реализаций, общих примеров и документации. Несовместимое изменение получает новую schema_version.
